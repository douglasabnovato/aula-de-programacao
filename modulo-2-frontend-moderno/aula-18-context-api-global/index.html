🌗 1. Prop Drilling e a Context API

🎯 Desafio

Na loja virtual fictícia Tear Mineiro, a escolha entre tema claro e escuro fica no App e precisa chegar ao botão do cabeçalho e aos cards de produto. Hoje a prop tema atravessa quatro componentes que não fazem nada com ela além de repassar. Como entregar esse dado direto a quem precisa?

Prop drilling é passar uma prop por componentes intermediários só para ela chegar lá embaixo. O Context cria um canal: um Provider no alto da árvore fornece o valor e qualquer descendente lê com useContext. Serve para dados usados por muitos componentes em níveis diferentes, como tema, usuário e idioma.

  • 📄 Passando dados profundamente com contexto — React O problema do prop drilling e o passo a passo de criar, fornecer e ler um contexto.
  • 📄 createContext — React Referência da função que cria o contexto e do componente Provider.
  • 📄 useContext — React Como um componente lê o contexto mais próximo acima dele na árvore.
  • 📄 Compartilhando estado entre componentes — React Elevar o estado, a alternativa que vem antes de pensar em contexto.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie o projeto tear-mineiro com Vite e monte a árvore App → Layout → Cabecalho → BotaoTema e Layout → Vitrine → CardProduto.
  2. Versão com Props: passe tema e alternarTema por todos os níveis e conte quantos componentes só repassam o valor.
  3. Criando o Contexto: crie src/contexts/TemaContext.jsx com export const TemaContext = createContext(null).
  4. Provedor: no mesmo arquivo, escreva TemaProvider com o useState do tema e devolva <TemaContext.Provider value={{ tema, alternarTema }}>.
  5. Envolvendo a Árvore: no App.jsx, coloque <TemaProvider> em volta do <Layout />.
  6. Consumindo: no BotaoTema, leia const { tema, alternarTema } = useContext(TemaContext).
  7. Removendo o Repasse: apague as props de tema de Cabecalho e Vitrine e confirme que tudo continua funcionando.
  8. Erro Provocado: Fora do Provedor: renderize um <BotaoTema /> fora do TemaProvider e observe o erro ao desestruturar null.
  9. Hook de Acesso: crie useTema(), que lê o contexto e lança um erro com mensagem clara quando ele for null, e use-o nos componentes.
  10. Validação e Testes: alterne o tema e confira no React Developer Tools que os intermediários não têm mais props de tema; registre no README o antes e o depois da árvore.

🛒 2. Estado Global com useReducer e Context

🎯 Desafio

O carrinho da Tear Mineiro é alterado em quatro lugares: o botão Comprar, o contador do cabeçalho, o painel do carrinho e o botão de esvaziar. Cada lugar tem um setCarrinho com uma lógica um pouco diferente, e o total já apareceu errado duas vezes. Como concentrar as regras do carrinho num lugar só e deixar qualquer componente disparar ações?

O useReducer move as regras de atualização para uma função pura, reducer(estado, acao). Junto com o Context, estado e dispatch ficam disponíveis na árvore, e os componentes passam a dizer o que aconteceu, como um produto adicionado, em vez de como o estado deve mudar.

  • 📄 Extraindo lógica de estado para um reducer — React Quando trocar vários setState por um reducer e como escrever as ações.
  • 📄 useReducer — React Referência do hook, incluindo a função de inicialização usada na próxima prática.
  • 📄 Escalando com reducer e contexto — React O padrão de combinar os dois para um estado global previsível.
  • 📄 Sintaxe de espalhamento — MDN O spread que cria arrays e objetos novos dentro do reducer.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie src/contexts/CarrinhoContext.jsx e reaproveite src/data/produtos.js com quatro produtos fictícios.
  2. Esqueleto do Reducer: escreva carrinhoReducer(itens, acao) com um switch para adicionado, quantidade_alterada, removido e esvaziado.
  3. Regra de Adição: se o produto já estiver no carrinho, some 1 na quantidade com map; se não, inclua com quantidade: 1.
  4. Erro Provocado: Mutação: no caso adicionado, use itens.push(...) e return itens, clique em Comprar e observe a tela parada.
  5. Ajuste Imutável: volte para [...itens, { ...acao.produto, quantidade: 1 }] e confirme que a tela atualiza.
  6. Provedor: crie CarrinhoProvider com useReducer(carrinhoReducer, []) e entregue { itens, dispatch } no value.
  7. Valores Derivados: em useCarrinho(), calcule quantidade e total com reduce, sem criar estado para eles.
  8. Disparando Ações: no botão Comprar, chame dispatch({ type: 'adicionado', produto }), e no cabeçalho mostre a quantidade.
  9. Painel do Carrinho: liste os itens com botões −, +, Remover e Esvaziar, cada um disparando sua ação.
  10. Validação e Testes: compre o mesmo produto duas vezes, ajuste quantidades até zero e esvazie; registre no README uma tabela com cada ação, seus dados e o efeito no carrinho.

🧭 3. Organização, Persistência e Limites do Contexto

🎯 Desafio

A Tear Mineiro colocou tema, carrinho e o texto da busca num único contexto. Agora, a cada letra digitada na busca, a página inteira renderiza de novo, e quem recarrega a página perde o carrinho. Como dividir os contextos, guardar o carrinho entre visitas e decidir o que realmente precisa ser global?

Todo componente que lê um contexto renderiza quando o value muda, por isso cada contexto deve ter uma responsabilidade e o value deve ser estável. Estado usado por uma só parte da tela continua local. Guardar o carrinho no localStorage é um efeito sincronizado com o estado.

  • 📄 useMemo — React Como manter o mesmo objeto de value entre renderizações enquanto os dados não mudam.
  • 📄 Pensando em React — React O passo de decidir onde cada estado deve viver, que evita globalizar o que é local.
  • 📄 Entendendo sua UI como uma árvore — React A árvore de renderização que explica quem renderiza de novo quando algo muda.
  • 📄 Usando a Web Storage API — MDN setItem, getItem e os limites do armazenamento local do navegador.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie um hook useRenders() com useRef e mostre em Cabeçalho, Vitrine e Rodapé quantas vezes cada um renderizou.
  2. Mapa de Uso: liste quem lê tema, carrinho e busca, e marque que só a Vitrine usa o texto da busca.
  3. Erro Provocado: Busca Global: coloque a busca no mesmo contexto do carrinho, digite algumas letras e observe o contador do Cabeçalho subir junto.
  4. Busca Local: mova a busca para um useState dentro da Vitrine e repita o teste.
  5. Provedores Separados: mantenha TemaProvider e CarrinhoProvider em arquivos distintos e componha os dois num componente Provedores.
  6. Value Estável: envolva o value em useMemo(() => ({ itens, dispatch }), [itens]) e faça o mesmo no tema.
  7. Carregando do Storage: passe uma função carregarInicial como terceiro argumento do useReducer, lendo localStorage.getItem('tear-carrinho') dentro de try/catch.
  8. Gravando a Cada Mudança: crie um useEffect com [itens] que grava JSON.stringify(itens) no storage.
  9. Componente Isolado: envolva o Rodapé com memo e confirme que ele não renderiza quando tema ou carrinho mudam.
  10. Validação e Testes: digite na busca, alterne o tema, compre e recarregue a página conferindo contadores e carrinho; registre no README o que ficou global e o que ficou local, com o motivo.
