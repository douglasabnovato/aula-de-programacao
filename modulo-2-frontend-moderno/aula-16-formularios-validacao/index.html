⌨️ 1. Inputs Controlados e Estado do Formulário

🎯 Desafio

O pet shop fictício Bicho Feliz recebe agendamentos de banho por um formulário com nome do tutor, telefone, porte do cachorro, serviço e aceite das regras. Hoje cada campo tem o próprio useState e a lógica de leitura se repete cinco vezes. Como guardar o formulário inteiro num estado só e ainda mostrar um resumo que muda enquanto a pessoa digita?

Num input controlado, o valor exibido vem do estado e cada digitação passa pelo onChange antes de aparecer. Com um objeto de estado e uma função de atualização genérica que lê name, value e checked, o mesmo código atende texto, select, radio e checkbox.

  • 📄 Componente input — React Referência do input no React: value, onChange, checked e o aviso de campo controlado sem manipulador.
  • 📄 Reagindo a entradas com estado — React Como pensar a interface como estados, a base de qualquer formulário.
  • 📄 Atualizando objetos no estado — React Por que se cria um objeto novo com spread em vez de alterar o existente.
  • 📄 Elemento label — MDN Como o rótulo se liga ao campo e por que isso importa para clique e leitor de tela.

✅ 2. Validação e Mensagens de Erro

🎯 Desafio

No Bicho Feliz, um em cada cinco agendamentos chega com telefone incompleto e a recepção perde tempo ligando para número errado. Mas mostrar todos os erros em vermelho assim que a página abre assusta quem nem começou a digitar. Como validar cada campo e exibir a mensagem certa só na hora certa?

A validação no navegador é uma função pura: recebe os valores e devolve os erros. Um estado de campos visitados controla quando a mensagem aparece, e aria-invalid com aria-describedby levam o erro também a quem usa leitor de tela. A validação no servidor continua obrigatória.

  • 📄 Validação de formulários — MDN Validação nativa do HTML, validação com JavaScript e os limites de cada uma.
  • 📄 Escolhendo a estrutura do estado — React Por que erros calculados a partir do formulário não devem virar outro estado.
  • 📄 aria-invalid — MDN Como sinalizar a tecnologias assistivas que o valor do campo não passou na validação.
  • 📄 aria-describedby — MDN Como ligar a mensagem de erro ao campo para que ela seja lida junto com o rótulo.

📨 3. Envio, Estados de Submissão e Retorno ao Usuário

🎯 Desafio

Quando a internet da recepção oscila, clientes do Bicho Feliz clicam três vezes em Agendar e o sistema grava três horários iguais. Quando dá erro, a tela não diz nada e a pessoa não sabe se precisa tentar de novo. Como controlar o envio para que aconteça uma vez só e o usuário sempre saiba o resultado?

O envio passa por estados: parado, enviando, sucesso e erro. O onSubmit concentra a lógica, o botão fica bloqueado enquanto a resposta não chega e o resultado é anunciado numa região aria-live. Nesta aula o servidor é simulado com uma Promise; a chamada HTTP real vem na Aula 17.

  • 📄 Componente form — React O componente form no React e as formas de tratar o envio.
  • 📄 Evento submit — MDN Quando o evento dispara e por que ele cobre tanto o clique quanto o Enter.
  • 📄 Event.preventDefault() — MDN Como impedir o comportamento padrão do navegador de recarregar a página.
  • 📄 aria-live — MDN Regiões que anunciam mudanças de conteúdo sem mover o foco.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie src/services/agendamentos.js com enviarAgendamento(dados), que devolve uma Promise resolvida após 1,5 s e rejeitada quando o nome for erro.
  2. Ligando o Envio: troque o botão para type="submit" e registre <form onSubmit={enviar}>.
  3. Erro Provocado: Recarga: escreva enviar sem evento.preventDefault(), clique em Agendar e observe a página recarregar e os dados sumirem.
  4. Estado do Envio: crie const [status, setStatus] = useState('parado') e a constante enviando derivada dele.
  5. Chamada Assíncrona: torne enviar uma função async e use try/catch em volta de await enviarAgendamento(form), trocando o status para sucesso ou erro.
  6. Bloqueio de Duplo Clique: use disabled={enviando} no botão, troque o texto para Enviando... e saia da função se ela já estiver enviando.
  7. Validação no Envio: se houver erros, marque todos os campos como visitados e chame evento.target.elements[primeiro].focus().
  8. Mensagem de Retorno: mostre o resultado num <p role="status" aria-live="polite"> com o protocolo ou o motivo da falha.
  9. Limpeza Após Sucesso: depois de confirmar, volte o formulário para inicial e zere os campos visitados.
  10. Validação e Testes: envie vazio, envie certo clicando várias vezes e envie com o nome erro; registre no README os quatro estados do envio e o que a tela mostra em cada um.
