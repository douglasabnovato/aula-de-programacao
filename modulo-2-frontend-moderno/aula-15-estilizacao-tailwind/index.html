🎨 1. Utility-First e Configuração com Vite

🎯 Desafio

A academia fictícia Pulso Fit tem um arquivo CSS de 1.200 linhas com classes como card-plano-destaque-novo2, e ninguém sabe o que pode ser apagado sem quebrar outra tela. A nova página de planos precisa sair esta semana. Como estilizar sem inventar mais nomes de classe e sem medo de efeito colateral?

O Tailwind entrega classes utilitárias pequenas, cada uma com uma responsabilidade (espaçamento, cor, tamanho), aplicadas direto no JSX. O estilo fica ao lado do componente e o CSS final contém só as classes que o projeto usa.

  • 📄 Styling with utility classes — Tailwind CSS A ideia central do utility-first e por que ela reduz o CSS que cresce sem controle.
  • 📄 Instalação com Vite — Tailwind CSS O passo a passo oficial com o plugin @tailwindcss/vite.
  • 📄 Preflight — Tailwind CSS O reset de estilos base que explica por que títulos e listas perdem a aparência padrão.
  • 📄 Play CDN — Tailwind CSS O build de navegador para prototipar sem instalar nada, e por que ele não vai para produção.

  • ▶️ CURSO DE TAILWIND PARA INICIANES | Tutorial Tailwind do ZERO Fernanda Kipper · 47:38 — Curso introdutório de Tailwind cobrindo a abordagem utility-first e as classes mais usadas.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie o projeto com npm create vite@latest pulso-fit -- --template react e instale npm install tailwindcss @tailwindcss/vite.
  2. Plugin no Vite: no vite.config.js, importe tailwindcss de @tailwindcss/vite e adicione tailwindcss() à lista plugins.
  3. Ligando o Tailwind: apague o conteúdo de src/index.css e deixe só @import "tailwindcss";.
  4. Primeiro Utilitário: no App.jsx, escreva <h1 className="text-3xl font-bold"> e confira o resultado no navegador.
  5. Erro Provocado: Sem Plugin: remova tailwindcss() do vite.config.js, reinicie o servidor e observe que as classes continuam no HTML mas nenhum estilo é aplicado; depois recoloque o plugin.
  6. Estrutura do Card: crie PlanoCard.jsx com um <article className="rounded-2xl bg-slate-800 p-6">.
  7. Tipografia: use text-2xl font-bold no nome, text-4xl no preço e text-slate-400 nos detalhes.
  8. Espaçamento e Lista: aplique space-y-4 no card e list-disc pl-5 na lista de benefícios, que o Preflight deixou sem marcadores.
  9. Botão do Plano: estilize o botão com w-full rounded-lg bg-emerald-400 py-2 font-semibold.
  10. Validação e Testes: rode npm run build, abra o CSS em dist/assets e procure uma classe que você não usou; registre no README o tamanho do arquivo e o que o Preflight mudou.
Concluiu todos os passos?

📱 2. Responsividade, Estados e Modo Escuro

🎯 Desafio

Oito em cada dez alunos da Pulso Fit abrem a página de planos no celular, onde os três cards ficam espremidos lado a lado. O botão também não dá retorno ao passar o mouse nem ao navegar pelo teclado, e parte do público pediu tema escuro. Como resolver os três pontos sem escrever media query à mão?

Prefixos como md: e lg: aplicam um utilitário a partir de uma largura de tela, no modelo mobile-first. Prefixos de estado (hover:, focus-visible:, disabled:) e o dark: seguem a mesma lógica para interação e tema.

  • 📄 Responsive design — Tailwind CSS Pontos de quebra, mobile-first e como combinar prefixos de largura.
  • 📄 Hover, focus e outros estados — Tailwind CSS A lista de prefixos de estado, incluindo focus-visible e disabled.
  • 📄 Dark mode — Tailwind CSS O prefixo dark: e como trocar a preferência do sistema por uma classe controlada pelo app.
  • 📄 Usando media queries — MDN O mecanismo de CSS que os prefixos geram por baixo.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: no projeto anterior, crie src/data/planos.js com três planos (Mensal, Semestral, Anual), um deles com destaque: true.
  2. Mobile Primeiro: monte a grade com grid gap-6 e confira no modo dispositivo do DevTools, em 375px, que os cards ficam um embaixo do outro.
  3. Pontos de Quebra: acrescente md:grid-cols-2 lg:grid-cols-3 e redimensione a janela até ver as três versões.
  4. Erro Provocado: Lógica Invertida: troque para grid-cols-3 sm:grid-cols-1 e observe três colunas espremidas no celular: sem prefixo vale para todas as larguras.
  5. Ajuste Mobile-First: volte para a versão base de uma coluna e anote no código a regra: o prefixo significa "a partir de".
  6. Resposta ao Mouse: adicione transition hover:-translate-y-1 hover:shadow-lg no card e hover:bg-emerald-600 no botão.
  7. Foco pelo Teclado: use focus-visible:outline-2 focus-visible:outline-offset-2 no botão e percorra a página só com Tab.
  8. Plano em Destaque: escolha as classes de borda e fundo com um ternário sobre plano.destaque e mostre um selo "Mais escolhido".
  9. Modo Escuro por Classe: no index.css, declare @custom-variant dark (&:where(.dark, .dark *));, crie um estado escuro que aplica a classe dark e use dark:bg-slate-800 nos cards.
  10. Validação e Testes: teste 375px, 768px e 1280px, navegue com Tab e alterne o tema; registre no README uma captura de cada largura.

🧩 3. Tema Próprio e Componentes Reutilizáveis

🎯 Desafio

O verde da Pulso Fit aparece como emerald-400 num arquivo, emerald-500 em outro e #34d399 num terceiro, e os mesmos cinco utilitários de botão estão copiados em 14 componentes. O marketing vai trocar a cor da marca no mês que vem. Como centralizar as decisões de design sem voltar ao CSS de 1.200 linhas?

No Tailwind v4 as decisões de design viram variáveis dentro de @theme, e cada uma gera utilitários com o nome da marca. A repetição de classes se resolve com um componente React com variantes, e não com uma classe CSS nova para cada caso.

  • 📄 Theme variables — Tailwind CSS Como o @theme define cores, fontes e espaçamentos que viram utilitários.
  • 📄 Colors — Tailwind CSS A paleta padrão e como acrescentar ou substituir cores do projeto.
  • 📄 Adding custom styles — Tailwind CSS Valores arbitrários, camadas e quando escrever CSS próprio faz sentido.
  • 📄 Functions and directives — Tailwind CSS Referência de @import, @theme, @custom-variant e das demais diretivas usadas na aula.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: abra src/index.css e liste, buscando no projeto, todas as cores verdes usadas hoje.
  2. Token de Cor: declare @theme { --color-marca: #22c55e; --color-marca-escura: #15803d; } abaixo do @import.
  3. Usando o Token: troque bg-emerald-400 por bg-marca e text-emerald-500 por text-marca.
  4. Fonte da Marca: declare --font-titulo no @theme e aplique font-titulo no título principal.
  5. Erro Provocado: Classe Montada: escreva className={`bg-${cor}-500`} com cor = 'emerald' e observe que o fundo não aparece: o Tailwind só gera classes escritas por inteiro no código.
  6. Ajuste com Mapa: crie um objeto variantes com strings completas, como primario: 'bg-marca text-white hover:bg-marca-escura'.
  7. Componente Botao: crie Botao.jsx recebendo variante, children e ...resto, repassando o resto ao <button>.
  8. Tamanhos: adicione a prop tamanho com um segundo mapa (sm e md) e valor padrão 'md'.
  9. Substituição Global: troque os botões dos cards pelo <Botao> e mude --color-marca para outra cor para ver a página inteira acompanhar.
  10. Validação e Testes: busque por emerald no projeto e confirme zero resultados fora do tema; registre no README a tabela de tokens e as variantes do Botao.
Concluiu todos os passos?
