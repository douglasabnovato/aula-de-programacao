🧭 1. SPAs e Rotas Declarativas

🎯 Desafio

O site fictício da Livraria Ipê tem Início, Catálogo e Contato num único componente, alternados por um estado e três condicionais. Quando o cliente recarrega a página ou manda o link do catálogo para uma amiga, o site abre sempre no Início. Como dar a cada tela o próprio endereço sem recarregar o site a cada clique?

Numa SPA o navegador baixa o HTML uma vez e o JavaScript troca as telas. O React Router liga cada endereço a um componente, mantém o histórico do navegador funcionando e troca só a parte da tela que mudou.

  • 📄 SPA (Single-page application) — MDN O que caracteriza uma aplicação de página única e o que ela deixa de fazer em relação ao site tradicional.
  • 📄 History API — MDN A API do navegador que o roteador usa por baixo para mudar a URL sem pedir uma página nova ao servidor.
  • 📄 Routing — React Router Como declarar Routes e Route no modo declarativo, incluindo rotas aninhadas e rota coringa.
  • 📄 Navigating — React Router Link, NavLink e navegação por código: as formas de trocar de rota.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie o projeto com npm create vite@latest livraria-ipe -- --template react, entre na pasta e rode npm install.
  2. Instalando o Roteador: rode npm install react-router e confira a versão registrada no package.json.
  3. Criando as Páginas: crie src/pages com Inicio.jsx, Catalogo.jsx e Contato.jsx, cada um devolvendo um <h1> e um parágrafo.
  4. Envolvendo a Aplicação: no main.jsx, importe BrowserRouter de react-router e envolva o <App /> com ele.
  5. Declarando as Rotas: no App.jsx, escreva um <Routes> com um <Route path="/" element={<Inicio />} /> para cada página.
  6. Erro Provocado: a Tag Errada: monte o menu com <a href="/catalogo">, abra a aba Rede do DevTools e observe o documento inteiro sendo baixado de novo a cada clique.
  7. Trocando por Link: substitua cada <a> por <Link to="/catalogo"> e confirme na aba Rede que só a tela muda.
  8. Página Não Encontrada: crie NaoEncontrada.jsx e registre a rota path="*" para qualquer endereço sem correspondência.
  9. Organizando o Menu: extraia o menu para src/components/Menu.jsx e coloque-o fora do <Routes>, para aparecer em todas as páginas.
  10. Validação e Testes: navegue pelo menu, use voltar e avançar do navegador, recarregue em /catalogo e digite /qualquer-coisa; registre no README a diferença entre <a> e <Link>.

🔗 2. Rotas Dinâmicas e Parâmetros de URL

🎯 Desafio

O catálogo da Livraria Ipê tem 300 livros, e escrever uma rota para cada um é inviável. Além disso, a equipe de vendas quer mandar para os clientes o link do catálogo já filtrado em "Infantis". Como uma única rota atende qualquer livro e o filtro fica guardado no próprio endereço?

Um segmento dinâmico como :id transforma parte da URL em parâmetro, lido com useParams. A query string (?categoria=) guarda estados que valem a pena compartilhar, lidos e escritos com useSearchParams.

  • 📄 URL Values — React Router Parâmetros de rota, query string e location: os três jeitos de ler dados da URL.
  • 📄 useParams — React Router Referência do hook que devolve os segmentos dinâmicos da rota atual.
  • 📄 useSearchParams — React Router Como ler e atualizar a query string sem montar a URL à mão.
  • 📄 URLSearchParams — MDN A API nativa que o hook devolve: get, set, delete e has.

  • ▶️ ReactJS - Como extrair parâmetros da url com React Router. Vinicius Dacal · 3:18 — Demonstra de forma rápida como extrair parâmetros da URL com React Router.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: no projeto da prática anterior, crie src/data/livros.js exportando um array de 6 livros fictícios com id, titulo, autora, categoria e preco.
  2. Listando o Catálogo: em Catalogo.jsx, percorra os livros com map e gere um <Link to={`/livros/${livro.id}`}> para cada um.
  3. Rota Dinâmica: no App.jsx, registre <Route path="/livros/:id" element={<DetalheLivro />} />.
  4. Lendo o Parâmetro: em DetalheLivro.jsx, leia const { id } = useParams() e mostre o valor na tela.
  5. Erro Provocado: Tipos: busque com livros.find((l) => l.id === id) e observe que nenhum livro é encontrado: o parâmetro chega como texto.
  6. Ajuste da Busca: converta com Number(id) e confirme que título, autora e preço aparecem.
  7. Livro Inexistente: quando o find devolver undefined, mostre uma mensagem e um link de volta ao catálogo.
  8. Filtro na URL: no catálogo, use const [searchParams, setSearchParams] = useSearchParams() e leia searchParams.get('categoria').
  9. Botões de Categoria: crie um botão por categoria chamando setSearchParams({ categoria: 'infantil' }) e um botão Todas com setSearchParams({}).
  10. Validação e Testes: abra direto /livros/3 e /livros/99, copie a URL filtrada para outra aba e confirme o mesmo resultado; registre no README por que o filtro foi para a URL e não para um useState.

🧱 3. Layouts Aninhados e Rotas Protegidas

🎯 Desafio

A Livraria Ipê ganhou uma área do cliente com Pedidos e Dados. As duas telas repetem o mesmo menu lateral copiado e colado, e qualquer pessoa que digite /conta/pedidos na barra de endereço vê a tela sem ter entrado. Como compartilhar o layout entre as telas e barrar quem não está logado?

Rotas aninhadas deixam um componente pai desenhar a moldura e um Outlet marcar onde entra a tela filha. Um componente guardião decide, antes de renderizar, se libera o Outlet ou redireciona com Navigate.

  • 📄 Outlet — React Router O ponto do layout onde a rota filha ativa é renderizada.
  • 📄 NavLink — React Router Link que sabe se está ativo, para destacar a tela atual no menu.
  • 📄 Navigate — React Router Redirecionamento declarativo, usado no guardião de rotas.
  • 📄 useNavigate — React Router Navegação por código, por exemplo depois de um login bem-sucedido.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie src/layouts/LayoutConta.jsx, src/components/RotaProtegida.jsx e src/pages/Conta.jsx com as telas Resumo, Pedidos, Dados e Entrar.
  2. Rota Pai: declare <Route path="/conta" element={<LayoutConta />}> com as filhas pedidos e dados, em caminho relativo, sem barra no início.
  3. Erro Provocado: Sem Outlet: acesse /conta/pedidos com o layout ainda sem <Outlet /> e observe que só o menu lateral aparece.
  4. Ajuste com Outlet: coloque <Outlet /> na área principal do layout e confirme que a tela filha surge ao lado do menu.
  5. Rota Índice: adicione <Route index element={<Resumo />} /> para o que aparece em /conta sem nada depois.
  6. Link Ativo: troque os links do menu lateral por NavLink com className={({ isActive }) => isActive ? 'ativo' : ''}.
  7. Estado de Sessão: no App.jsx, crie const [usuario, setUsuario] = useState(null); na tela Entrar, grave o usuário e chame navegar('/conta') vindo de useNavigate().
  8. Guardião de Rotas: em RotaProtegida.jsx, devolva <Navigate to="/entrar" replace /> quando não houver usuário e <Outlet /> quando houver.
  9. Encaixando o Guardião: envolva a rota /conta com <Route element={<RotaProtegida usuario={usuario} />}>.
  10. Validação e Testes: tente abrir /conta/pedidos sem login, entre, navegue pelo menu lateral, saia e use o botão voltar; registre no README o que o replace mudou no histórico.
Concluiu todos os passos?
