🌐 1. Buscando Dados com fetch e useEffect

🎯 Desafio

A startup fictícia Entrega Já guarda as tarefas da equipe numa API REST. O painel em React mostra uma lista vazia por alguns segundos, e quando a API cai a tela continua vazia, sem explicação nenhuma. Como buscar os dados ao abrir a página e mostrar carregando, erro ou lista conforme o caso?

O fetch devolve uma Promise com a resposta HTTP, e um status 404 ou 500 não é tratado como erro automaticamente. Em React a busca é um efeito colateral, por isso fica dentro de um useEffect, e a tela é decidida por três estados: carregando, erro e dados.

  • 📄 Usando Fetch — MDN Como fazer requisições, ler o corpo em JSON e checar o status da resposta.
  • 📄 Sincronizando com efeitos — React Por que buscar dados é um efeito e como o array de dependências controla quando ele roda.
  • 📄 REST — Glossário MDN O estilo de arquitetura por trás das APIs que o frontend consome.
  • 📄 Códigos de status HTTP — MDN O significado de cada faixa de status e quais delas o painel precisa tratar.

  • ▶️ Buscando dados de uma API com useEffect no React - Fetching data #CursoDeReactNextJS Rafael Fischer - Dev & Design · 8:40 — Busca dados de uma API com useEffect e guarda o resultado no estado do componente.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie o projeto entrega-ja com Vite e abra https://jsonplaceholder.typicode.com/todos?userId=1 no navegador para conhecer o formato do JSON.
  2. Três Estados: em PainelTarefas.jsx, declare tarefas (array vazio), carregando (true) e erro (null).
  3. Erro Provocado: Busca Solta: chame o fetch com setTarefas direto no corpo do componente e observe na aba Rede as requisições se repetindo sem parar.
  4. Efeito de Montagem: mova a busca para um useEffect com [], dentro de uma função async function carregar() chamada logo em seguida.
  5. Lendo o JSON: use const resposta = await fetch(URL) e await resposta.json() e guarde o resultado com setTarefas.
  6. Checando o Status: troque a URL para /todoss, veja que o 404 não cai no catch e acrescente if (!resposta.ok) throw new Error(...).
  7. Finalizando o Carregamento: use try/catch/finally e desligue o carregando no finally.
  8. Telas Antecipadas: antes do return principal, devolva a mensagem de carregando e, depois, a de erro com um botão Tentar de novo que incrementa um estado tentativa usado como dependência.
  9. Lista Final: renderize as tarefas com map e key={t.id}, riscando as que têm completed verdadeiro.
  10. Validação e Testes: com a aba Rede, teste Slow 3G e Offline e clique em Tentar de novo; registre no README o que aparece em cada um dos três estados.

✏️ 2. Criando, Atualizando e Excluindo com POST, PATCH e DELETE

🎯 Desafio

A equipe da Entrega Já quer criar tarefas, marcá-las como feitas e apagar as canceladas direto no painel. Cada ação precisa chegar à API, e a lista na tela tem que refletir o resultado sem buscar tudo de novo a cada clique. Como enviar cada operação com o método HTTP certo e manter o estado em dia?

Numa API REST o método diz a intenção: POST cria, PATCH altera parte de um recurso e DELETE remove. O corpo vai em JSON com o cabeçalho Content-Type, e a resposta atualiza o estado com map e filter, sem alterar o array original.

  • 📄 Métodos HTTP — MDN GET, POST, PATCH, PUT e DELETE, com a semântica de cada um.
  • 📄 fetch() — MDN As opções de method, headers e body que transformam o fetch numa escrita.
  • 📄 JSON.stringify() — MDN Como o objeto JavaScript vira o texto que viaja no corpo da requisição.
  • 📄 Atualizando arrays no estado — React Incluir, trocar e remover itens sem mutar o array, com spread, map e filter.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie GerenciadorTarefas.jsx carregando as cinco primeiras tarefas com ?userId=1&_limit=5 e um formulário com campo e botão Adicionar.
  2. Criando com POST: no envio, chame fetch(API, { method: 'POST', body: JSON.stringify({ title, completed: false, userId: 1 }) }).
  3. Erro Provocado: Sem Cabeçalho: envie sem headers, veja na aba Rede que a resposta traz só o id e acrescente { 'Content-Type': 'application/json' }.
  4. Inserindo na Lista: coloque a tarefa criada no topo com setTarefas((atuais) => [nova, ...atuais]) e limpe o campo.
  5. Ids da API de Teste: note que a API devolve sempre o mesmo id para itens novos e gere um id local com Date.now(), marcando a tarefa com local: true.
  6. Atualizando com PATCH: no checkbox, envie PATCH para /todos/${id} com { completed: !tarefa.completed } e troque o item com map.
  7. Excluindo com DELETE: no botão Excluir, envie DELETE e remova o item com filter.
  8. Tratando Falhas: em cada operação, confira resposta.ok, lance um erro com o status e mostre a mensagem acima da lista.
  9. Bloqueio por Item: guarde em ocupado o id da tarefa em andamento e desabilite só os controles dela.
  10. Validação e Testes: crie, marque e exclua tarefas conferindo na aba Rede o método e o status de cada requisição; registre no README uma tabela ação, método e status esperado.

🗂️ 3. Camada de Serviço, Hook Personalizado e Cancelamento

🎯 Desafio

O painel da Entrega Já cresceu: a URL da API está repetida em nove componentes, cada tela reescreve o mesmo trio carregando, erro e dados, e quando alguém troca rápido de pessoa no seletor a lista às vezes mostra as tarefas da pessoa anterior. Como organizar o acesso à API num lugar só e evitar respostas que chegam fora de ordem?

Um módulo de serviço concentra a URL base, os cabeçalhos e a checagem de status. Um hook personalizado concentra os três estados da busca. E o AbortController, chamado na limpeza do useEffect, cancela a requisição antiga quando a dependência muda, eliminando a condição de corrida.

  • 📄 Reutilizando lógica com hooks personalizados — React Como extrair estados e efeitos repetidos para uma função use própria.
  • 📄 Talvez você não precise de um efeito — React Inclui a seção sobre busca de dados e condições de corrida com a solução pela limpeza do efeito.
  • 📄 AbortController — MDN O objeto que cancela uma ou mais requisições pelo signal.
  • 📄 try...catch — MDN Captura de erros e como distinguir um cancelamento de uma falha real.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie src/services/api.js e src/hooks/useBusca.js no projeto da aula.
  2. URL Base Única: em api.js, declare BASE_URL e a função requisitar(caminho, opcoes), que monta a URL, confere resposta.ok e devolve o JSON.
  3. Cabeçalho Condicional: envie Content-Type só quando houver body, para não gerar verificações extras do navegador nos GET.
  4. Hook useBusca: mova dados, carregando e erro para useBusca(caminho), com um useEffect dependente de [caminho].
  5. Seletor de Pessoa: em PainelEquipe.jsx, use useBusca('/users') para preencher um <select> e guarde a escolha em usuarioId.
  6. Lista Dependente: chame useBusca(`/todos?userId=${usuarioId}`) e mostre as tarefas da pessoa escolhida.
  7. Erro Provocado: Corrida: com a aba Rede em Slow 3G e ainda sem cancelamento, troque de pessoa várias vezes rápido e observe respostas antigas chegando depois das novas.
  8. Cancelamento: no efeito, crie const controle = new AbortController(), passe signal: controle.signal e devolva () => controle.abort().
  9. Ignorando o Abort: no catch, só registre o erro se falha.name !== 'AbortError'.
  10. Validação e Testes: repita a troca rápida e confira as requisições canceled na aba Rede e a lista sempre da pessoa certa; registre no README o papel de cada camada.
