Explicação de Projeto em Cinco Minutos — Modelo Preenchido

Aula 56 · Módulo 6: Soft Skills, Carreira e Inteligência Emocional · ByteClass

O que esta atividade entrega

O roteiro da candidata fictícia Sofia Andrade para explicar o projeto Agenda de Monitorias, na ordem problema, desenho, decisões, limite e próximo passo.

1. Problema (40 segundos)

  • Alunos da escola fictícia marcavam monitoria por mensagem e os horários se sobrepunham.
  • O projeto permite ver horários livres e reservar um horário sem conflito.

2. Desenho (1 minuto)

  • Frontend em React publicado estaticamente.
  • API em Express com rotas de horários e reservas.
  • Banco PostgreSQL com tabelas de monitor, horário e reserva.
  • Camadas: telas (apresentação), regra de conflito no serviço (domínio), repositório SQL (dados).

3. Três decisões (1 minuto e 30 segundos)

  • Regra de conflito no banco com restrição única, e não só no frontend — alternativa descartada: validar só na tela, porque duas pessoas podem reservar ao mesmo tempo.
  • Monólito com uma API só — alternativa descartada: serviço separado para notificações, porque ainda não havia volume que justificasse.
  • Autenticação por e-mail da escola — alternativa descartada: cadastro livre, porque o público é fechado.

4. Limite conhecido (40 segundos)

  • Sem fila de espera: quando o horário lota, o aluno não é avisado se alguém cancelar. Descobri ao testar com a turma.

5. Próximo passo com dez vezes mais usuários (1 minuto)

  • Primeiro, mover configuração para variáveis de ambiente por ambiente e ter réplicas da API sem estado.
  • Depois, índice na coluna de data das reservas, que é a consulta mais frequente.

O que observar

  • A ordem começa pelo problema; as telas aparecem só como consequência.
  • Cada decisão vem com a alternativa descartada — é isso que mostra raciocínio.
  • Dizer um limite real antes de perguntarem aumenta a confiança na explicação.
