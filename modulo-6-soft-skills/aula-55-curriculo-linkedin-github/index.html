📄 1. Currículo Técnico de Uma Página

🎯 Desafio

O candidato fictício Rafael Tavares enviou para a vaga de desenvolvedor júnior da empresa fictícia Serra Digital um currículo de três páginas com foto, CPF, estado civil e a frase 'proativo e comunicativo'. O recrutador leu por menos de um minuto e não encontrou nenhum projeto. O que precisa sair, o que precisa entrar e em que ordem?

O currículo técnico é um documento de triagem: quem lê procura, em poucos segundos, se há função, tecnologia e evidência compatíveis com a vaga. Cada linha precisa ser verificável, e dados pessoais além do necessário para contato não ajudam na seleção e ainda expõem o candidato. A LGPD define o que é dado pessoal, e a Lei 9.029 proíbe exigências discriminatórias na admissão.

  • 📄 Lei Geral de Proteção de Dados (Lei 13.709/2018) — Planalto O que conta como dado pessoal e sensível: base para decidir o que não vai no currículo.
  • 📄 Lei 9.029/1995 — Planalto Proíbe práticas discriminatórias no acesso ao emprego: por que estado civil e foto não são exigência.
  • 📄 Classificação Brasileira de Ocupações — site oficial Títulos de ocupação reconhecidos para nomear o cargo pretendido.
  • 📄 Tecnologias — Stack Overflow Survey 2025 O nome correto das linguagens e ferramentas, para escrever como o mercado procura.

  • ▶️ Programador INICIANTE - Esse curriculo é para voce! Fiasco · 6:38 — Apresenta um modelo de currículo para programador iniciante e o que destacar nele.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: abra o seu currículo atual, ou crie um arquivo curriculo.md, e separe uma vaga real que você gostaria de disputar.
  2. Lendo a Vaga: sublinhe na vaga a função, as tecnologias obrigatórias e o tipo de problema que o time resolve.
  3. Limpando Dados Pessoais: remova CPF, RG, foto, estado civil e endereço completo; mantenha nome, cidade, e-mail, telefone, LinkedIn e GitHub.
  4. Título e Resumo: use a versão de uma linha do seu posicionamento como título e a de três linhas como resumo.
  5. Projetos Antes de Tudo: para quem busca a primeira vaga, coloque os projetos logo após o resumo, cada um com link publicado.
  6. Frase de Evidência: escreva cada item como ação + tecnologia + resultado verificável, por exemplo: construí painel em React que lista 200 pedidos com filtro por status.
  7. Erro Provocado: escreva três itens com adjetivos como 'proativo' e 'dedicado', peça a um colega que aponte onde está a prova, e observe que ele não encontra.
  8. Ajustando: troque cada adjetivo por um fato: o que você fez, com o quê e o que mudou.
  9. Cabendo em Uma Página: corte experiências sem relação com a vaga para uma linha só e confira que tudo cabe numa página em PDF.
  10. Validação e Testes: dê o PDF a alguém por trinta segundos e pergunte para qual vaga você serve e qual projeto lembrou; registre a resposta no README.
Concluiu todos os passos?

🔗 2. LinkedIn: Perfil que Recrutador Encontra e Entende

🎯 Desafio

A recrutadora fictícia Patrícia Lemos, da empresa fictícia Vale Sistemas, busca 'desenvolvedor frontend React Juiz de Fora' e o perfil do aluno Diego Faria não aparece, porque o título dele diz apenas 'Estudante'. Quando ela chega ao perfil por indicação, o campo Sobre está vazio. Como o perfil passa a ser encontrado na busca e entendido na primeira tela?

O LinkedIn funciona como um buscador: título, localização, competências e experiências são os campos que fazem o perfil aparecer, e a primeira tela decide se a pessoa continua lendo. O conteúdo é o mesmo do currículo, organizado para leitura rápida e com as palavras que o mercado usa. O que é público precisa ser escolhido com o mesmo cuidado com dados pessoais do currículo.

  • 📄 CBO — Ministério do Trabalho e Emprego Nomes de cargo reconhecidos para usar no título e nas experiências.
  • 📄 Hierarquia visual — Nielsen Norman Group Como leitores escaneiam uma tela: base para ordenar título, resumo e destaques.
  • 📄 Perfil dos desenvolvedores — Stack Overflow Survey 2025 Os nomes de função usados pela área, como frontend, backend e fullstack.
  • 📄 Trabalho — Stack Overflow Survey 2025 Regimes de trabalho e busca por nova vaga entre desenvolvedores.

  • ▶️ LinkedIn para PROGRAMADORES iniciantes (guia prático) Igor Mucharski · 8:32 — Guia prático de LinkedIn para programadores iniciantes serem encontrados por recrutadores.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: abra o seu perfil no LinkedIn em uma aba e o currículo da prática anterior em outra.
  2. Teste de Busca: numa janela anônima, pesquise o cargo e a cidade que você quer e anote se o seu perfil aparece nos resultados.
  3. Título: troque o título pela versão de uma linha do seu posicionamento, com função e tecnologia principal.
  4. Localização e Modalidade: confira a cidade e informe se aceita presencial, híbrido ou remoto.
  5. Campo Sobre: escreva três parágrafos curtos: o que você faz, dois projetos com link e o tipo de vaga que busca.
  6. Erro Provocado: cole no Sobre o texto corrido do currículo antigo, sem quebras, e peça a um colega para achar o link do seu projeto em dez segundos.
  7. Ajustando: quebre o texto em parágrafos curtos e coloque os links dos projetos na seção de destaques.
  8. Competências: cadastre as tecnologias exatamente com os nomes usados nas vagas que você coletou.
  9. Privacidade: revise o que está público: telefone e e-mail pessoal só se você quiser contato direto de desconhecidos.
  10. Validação e Testes: repita o teste de busca após alguns dias, compare com o resultado inicial e registre no README o antes e o depois do título.
Concluiu todos os passos?

🐙 3. GitHub como Portfólio Verificável

🎯 Desafio

O aluno fictício Lucas Nogueira tem 38 repositórios no GitHub: 30 são exercícios sem README, dois têm arquivo .env com chave de API e nenhum tem link para o projeto rodando. O tech lead da empresa fictícia Ponte Tech abriu três repositórios e desistiu. Quais repositórios devem aparecer primeiro e o que cada um precisa mostrar?

Para quem busca a primeira vaga, o GitHub é a prova do que o currículo afirma. Quem avalia abre poucos repositórios e procura três coisas: se o projeto roda, se o README explica o problema e as decisões, e se o código tem cuidado básico, como segredos fora do repositório. Publicar com GitHub Pages ou com uma pipeline de integração contínua transforma o repositório em algo que se testa com um clique.

  • 📄 Criando um site com GitHub Pages — GitHub Docs Publicar o projeto para que o avaliador veja funcionando sem clonar nada.
  • 📄 Início rápido do GitHub Actions — GitHub Docs Uma pipeline simples que roda testes a cada push e mostra o selo verde no repositório.
  • 📄 Architectural Decision Records — ADR Formato curto para registrar decisões técnicas e mostrar raciocínio, não só código.
  • 📄 The Twelve-Factor App — Configuração Por que chaves e senhas ficam em variáveis de ambiente e fora do repositório.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: abra a lista dos seus repositórios e crie uma planilha com nome, descrição, se tem README, se tem link publicado e se há segredo no histórico.
  2. Escolhendo os Seis: escolha até seis repositórios que provam o seu posicionamento; eles serão os fixados no perfil.
  3. Procurando Segredos: pesquise nos seis por .env, apiKey e password; se achar chave real, revogue a chave no serviço antes de qualquer outra ação.
  4. Corrigindo a Configuração: mova valores sensíveis para variáveis de ambiente, adicione .env ao .gitignore e crie um .env.example sem valores reais.
  5. README com Estrutura: escreva em cada README: problema, como rodar, tecnologias, decisões e link publicado.
  6. Publicando: publique os projetos de frontend com GitHub Pages e coloque o link no campo de descrição do repositório.
  7. Erro Provocado: peça a um colega para rodar um dos projetos seguindo só o README, sem sua ajuda, e anote em que passo ele travou.
  8. Ajustando: reescreva o trecho do README em que o colega travou, com o comando exato.
  9. Organizando o Resto: arquive ou torne privados os exercícios que não representam o seu nível atual.
  10. Validação e Testes: fixe os seis repositórios no perfil, abra o perfil deslogado e confira em trinta segundos se dá para entender o que você faz; registre no README do perfil.
Concluiu todos os passos?
