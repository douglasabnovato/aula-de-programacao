Primeiros Comandos e o que Cada Um Mostra

Aula 32 · Módulo 4: Fullstack, DevOps e Projeto Final · ByteClass

Roteiro de exploração

# A imagem é o molde; o contêiner é a execução dela.
docker pull node:20-alpine
docker images                 # os moldes que você tem
docker ps                     # o que está rodando agora
docker ps -a                  # inclusive o que já parou

# Entrar num contêiner e olhar de dentro
docker run -it node:20-alpine sh
  node --version
  ls /                        # não é o seu sistema de arquivos
  exit

docker ps -a                  # ele parou, mas continua existindo
docker rm <id>                # agora sim, removido

Comparando tamanhos

docker pull node:20
docker pull node:20-alpine
docker images | grep node

A diferença costuma passar de 900 MB. Numa esteira de CI que constrói dez vezes por dia, isso é tempo e banda todo dia.

Imagem × contêiner, em uma frase

A imagem é a receita congelada, imutável, que você distribui. O contêiner é uma execução dessa receita, com sistema de arquivos próprio e descartável. Uma imagem gera quantos contêineres você quiser.

Contêiner não é máquina virtual

  • A VM carrega um sistema operacional inteiro; o contêiner usa o núcleo do host.
  • Por isso a VM sobe em minutos e o contêiner em segundos.
  • E por isso o contêiner Linux precisa de um núcleo Linux — no Windows, quem fornece é o WSL.
