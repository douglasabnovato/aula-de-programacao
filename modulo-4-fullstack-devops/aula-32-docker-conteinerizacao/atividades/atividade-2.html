Dockerfile da API — com a Ordem Certa

Aula 32 · Módulo 4: Fullstack, DevOps e Projeto Final · ByteClass

Dockerfile

FROM node:20-alpine

WORKDIR /app

# Copiar só o manifesto primeiro: enquanto as dependências não mudarem,
# o Docker reaproveita esta camada e pula o npm ci inteiro.
COPY package*.json ./
RUN npm ci --omit=dev

COPY . .

EXPOSE 3000

CMD ["node", "app.js"]

.dockerignore

node_modules
npm-debug.log
.env
.git
.gitignore
dist
coverage
*.md

O experimento que prova o cache

  1. docker build -t minha-api . — cronometre.
  2. Altere uma linha em app.js.
  3. docker build -t minha-api . de novo — cronometre.

O segundo build deve ser muito mais rápido: o npm ci veio do cache.

Agora inverta a ordem e refaça

# Versão errada, para você sentir a diferença:
COPY . .
RUN npm ci --omit=dev

Com COPY . . antes, qualquer alteração de uma vírgula no código invalida a camada seguinte e o npm ci roda de novo, toda vez.

Por que CMD em array

CMD ["node", "app.js"] executa o processo diretamente. CMD node app.js passa por um shell, e aí o sinal de parada do Docker chega no shell em vez de chegar no Node — o contêiner demora dez segundos para morrer e não desliga direito.
