📦 1. Imagem, Contêiner e o Problema que Isso Resolve

🎯 Desafio

A escola fictícia CódigoMinas recebe alunos com Windows, macOS e Linux, e a mesma API funciona em uns e quebra em outros por versão diferente do Node. Instalar tudo à mão em cada máquina leva uma aula inteira. O que é um contêiner e por que ele sobe em segundos quando uma máquina virtual levaria minutos?

Contêiner não é máquina virtual. Entender a diferença explica por que ele sobe em segundos e por que a imagem precisa ser construída de forma enxuta.

  • 📄 Visão Geral do Docker — documentação oficial A arquitetura em uma página: cliente, daemon, imagem, contêiner e registro.
  • 📄 O que é um Contêiner — Docker A explicação conceitual com comparação direta com máquina virtual.
  • 📄 Referência da CLI do Docker Todos os comandos, com as opções de cada um.
  • 📄 Imagem oficial do Node no Docker Hub As variantes disponíveis e a diferença entre a tag padrão e a alpine.

  • ▶️ Você NÃO sabe Docker se não entender isso: A Teoria Fundamental (Imagem vs Container) - Aula #04 CFBCursos · 11:36 — Explica a diferença entre imagem e contêiner, a base teórica do Docker.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: confirme a instalação com docker --version e docker run hello-world.
  2. Baixando uma Imagem: rode docker pull node:20-alpine e observe as camadas sendo baixadas.
  3. Listando o que Existe: compare docker images com docker ps -a e anote a diferença.
  4. Contêiner Interativo: entre com docker run -it node:20-alpine sh e rode node --version dentro.
  5. Explorando o Isolamento: dentro do contêiner, rode ls / e compare com o seu sistema.
  6. Saindo e Verificando: digite exit e confirme com docker ps -a que o contêiner parou mas existe.
  7. Limpando: remova o contêiner parado com docker rm usando o id listado.
  8. Comparando Tamanhos: baixe node:20 e compare o tamanho com a variante alpine.
  9. Registrando a Diferença: escreva no README quantos MB a escolha da tag economizou.
  10. Validação e Testes: explique com suas palavras, por escrito, a diferença entre imagem e contêiner.

📝 2. Escrevendo o Dockerfile da Sua API

🎯 Desafio

A equipe da CódigoMinas gera a imagem da API a cada alteração, e cada build leva três minutos porque reinstala todas as dependências mesmo quando só uma linha do código mudou. Como escrever o Dockerfile para que a mudança de código não refaça o que não mudou?

Cada linha do Dockerfile é uma camada em cache. A ordem das instruções decide se o build leva três segundos ou três minutos a cada alteração de código.

  • 📄 Referência do Dockerfile Cada instrução, com sintaxe e comportamento, na documentação oficial.
  • 📄 Boas Práticas de Build — Docker As recomendações oficiais sobre ordem, cache, tamanho e segurança.
  • 📄 Builds Multi-estágio Como compilar num estágio e copiar só o resultado para a imagem final.
  • 📄 Contexto de Build e .dockerignore O que é enviado ao daemon e como reduzir esse envio.
🎥 Vídeos de apoio
  • ▶️ Dockerizando aplicações Node.js 📦🚀 Waldemar Neto - Dev Lab · 36:41 — Mostra como escrever um Dockerfile para uma aplicação Node.js e gerar a imagem.
  • ▶️ NodeJS Docker, como utilizar Programando Soluções · 11:04 — Demonstra como colocar uma aplicação Node.js para rodar dentro de um contêiner Docker.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: abra a pasta da API da aula 23 e crie um arquivo chamado Dockerfile.
  2. Imagem Base: declare FROM node:20-alpine como primeira linha.
  3. Diretório de Trabalho: defina WORKDIR /app para não espalhar arquivos na raiz.
  4. Aproveitando o Cache: copie só package*.json e rode npm ci antes de copiar o resto.
  5. Copiando o Código: só então use COPY . . para trazer os arquivos da aplicação.
  6. Ignorando o Desnecessário: crie .dockerignore com node_modules, .env e .git.
  7. Declarando a Porta: acrescente EXPOSE 3000 como documentação da imagem.
  8. Comando de Início: finalize com CMD [\"node\", \"app.js\"] na forma de array.
  9. Construindo: rode docker build -t minha-api . e acompanhe cada camada.
  10. Validação e Testes: suba com docker run -p 3000:3000 minha-api, teste no navegador, altere uma linha do código e refaça o build cronometrando.

💾 3. Volumes, Variáveis e o Contêiner que Não Perde Dado

🎯 Desafio

A API da CódigoMinas roda em contêiner, mas toda vez que o contêiner é recriado as tarefas cadastradas desaparecem, e trocar a porta exige gerar uma imagem nova. Como guardar o dado fora do contêiner e mudar a configuração sem rebuild?

Contêiner é descartável por natureza: quando ele morre, o que estava dentro vai junto. Volume e variável de ambiente são o que separa um brinquedo de algo utilizável.

  • 📄 Volumes — documentação oficial Como criar, montar e inspecionar volumes, e quando usar cada tipo.
  • 📄 Bind Mounts — Docker Montar uma pasta do host dentro do contêiner, útil em desenvolvimento.
  • 📄 docker run — todas as opções A referência de -p, -v, -e, --name e o resto das flags.
  • 📄 Redes no Docker Como contêineres se enxergam e por que localhost dentro do contêiner não é o seu localhost.
🎥 Vídeos de apoio
  • ▶️ 21 Volumes e Variáveis de Ambiente no Docker Compose Erudio · 5:47 — Mostra como declarar volumes e variáveis de ambiente para os serviços no Docker Compose.
  • ▶️ O que são volumes Docker JLCP · 8:24 — Explica o que são volumes Docker e como eles mantêm os dados quando o contêiner é removido.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: suba a API em contêiner e crie três tarefas pela rota POST.
  2. Provocando a Perda: pare e remova o contêiner, suba de novo e confirme que as tarefas sumiram.
  3. Criando o Volume: rode docker volume create dados-api.
  4. Montando o Volume: suba com -v dados-api:/app/dados e faça a API gravar nessa pasta.
  5. Provando a Persistência: repita o ciclo de parar, remover e subir, e confirme que o dado permaneceu.
  6. Passando Configuração: use -e PORT=4000 e confirme que a porta mudou sem novo build.
  7. Arquivo de Ambiente: troque as flags por --env-file .env e verifique o mesmo resultado.
  8. Montando o Código: use -v $(pwd):/app para desenvolvimento e edite um arquivo com o contêiner no ar.
  9. Nomeando e Inspecionando: use --name api e rode docker logs api e docker inspect api.
  10. Validação e Testes: documente no README o comando completo de execução, com volume e env-file.
