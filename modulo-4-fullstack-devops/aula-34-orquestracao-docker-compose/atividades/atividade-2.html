Banco Persistente com Healthcheck — Código de Referência

Aula 34 · Módulo 4: Fullstack, DevOps e Projeto Final · ByteClass

O que esta atividade entrega

O mesmo projeto agora com volume nomeado para os dados, carga inicial por script SQL e a API esperando o banco ficar healthy antes de subir.

compose.yaml

# Início: compose.yaml — banco com volume, script de carga e healthcheck; API esperando o banco saudável
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: tarefas
      POSTGRES_PASSWORD: senha_local_exemplo
      POSTGRES_DB: tarefas
    volumes:
      - dados-pg:/var/lib/postgresql/data
      - ./db/init.sql:/docker-entrypoint-initdb.d/01-init.sql:ro
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U tarefas -d tarefas"]
      interval: 5s
      timeout: 3s
      retries: 10

  api:
    build: ./api
    environment:
      PORT: 3000
      DATABASE_URL: postgres://tarefas:senha_local_exemplo@db:5432/tarefas
    ports:
      - "3000:3000"
    restart: on-failure
    depends_on:
      db:
        condition: service_healthy

volumes:
  dados-pg:
# Fim de compose.yaml

db/init.sql

-- Início: init.sql — executa só na primeira subida, com a pasta de dados vazia
CREATE TABLE IF NOT EXISTS tarefas (
  id SERIAL PRIMARY KEY,
  titulo TEXT NOT NULL,
  feita BOOLEAN NOT NULL DEFAULT false
);

INSERT INTO tarefas (titulo, feita) VALUES
  ('Configurar o volume do banco', true),
  ('Testar o healthcheck', false);
-- Fim de init.sql

Como rodar

  1. Crie a pasta db/ e salve o init.sql
  2. Rode docker compose up --build e acompanhe o banco passar de starting para healthy em docker compose ps
  3. Acesse http://localhost:3000/tarefas e confira as duas tarefas da carga inicial
  4. Rode docker compose down e docker compose up: os dados continuam
  5. Rode docker compose down -v para apagar o volume e recomeçar do zero

O que observar

  • O init.sql não roda de novo enquanto o volume existir — alterar o script sem apagar o volume não muda nada.
  • Com condition: service_healthy, o log mostra a API iniciando só depois do pg_isready responder.
  • down remove contêineres e rede; down -v remove também o volume, e com ele todo o dado.
