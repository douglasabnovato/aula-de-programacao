Compose por Ambiente — Código de Referência

Aula 34 · Módulo 4: Fullstack, DevOps e Projeto Final · ByteClass

O que esta atividade entrega

Um compose.yaml base sem segredo, um compose.override.yaml lido automaticamente em desenvolvimento, um compose.prod.yaml combinado por -f e um serviço de apoio que só sobe com perfil.

.env.example

# Início: .env.example — copie para .env e troque os valores; o .env não vai para o Git
POSTGRES_USER=tarefas
POSTGRES_DB=tarefas
POSTGRES_PASSWORD=troque-aqui
# Fim de .env.example

compose.yaml

# Início: compose.yaml — descrição base da aplicação, igual em todos os ambientes
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-tarefas}
      POSTGRES_DB: ${POSTGRES_DB:-tarefas}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?defina POSTGRES_PASSWORD no .env}
    volumes:
      - dados-pg:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-tarefas} -d ${POSTGRES_DB:-tarefas}"]
      interval: 5s
      timeout: 3s
      retries: 10

  api:
    build: ./api
    environment:
      PORT: 3000
      DATABASE_URL: postgres://${POSTGRES_USER:-tarefas}:${POSTGRES_PASSWORD:?defina POSTGRES_PASSWORD no .env}@db:5432/${POSTGRES_DB:-tarefas}
    ports:
      - "3000:3000"
    depends_on:
      db:
        condition: service_healthy

  adminer:
    image: adminer
    profiles: ["ferramentas"]
    ports:
      - "8080:8080"
    depends_on:
      - db

volumes:
  dados-pg:
# Fim de compose.yaml

compose.override.yaml

# Início: compose.override.yaml — só desenvolvimento; lido automaticamente pelo docker compose
services:
  db:
    ports:
      - "5432:5432"

  api:
    environment:
      NODE_ENV: development
    command: ["node", "--watch", "app.js"]
    develop:
      watch:
        - action: sync
          path: ./api/src
          target: /app/src
        - action: sync
          path: ./api/app.js
          target: /app/app.js
        - action: rebuild
          path: ./api/package.json
# Fim de compose.override.yaml

compose.prod.yaml

# Início: compose.prod.yaml — só produção; combinado com o base usando -f
services:
  api:
    environment:
      NODE_ENV: production
    restart: unless-stopped

  db:
    restart: unless-stopped
# Fim de compose.prod.yaml

Como rodar

  1. Copie .env.example para .env e defina a senha
  2. Desenvolvimento: docker compose watch (usa base + override)
  3. Com o painel do banco: docker compose --profile ferramentas up e abra http://localhost:8080
  4. Produção: docker compose -f compose.yaml -f compose.prod.yaml up -d --build
  5. Para conferir qualquer combinação antes de subir: acrescente config no lugar de up

O que observar

  • O override só é lido quando nenhum -f é passado; em produção ele fica de fora e a porta 5432 não é publicada.
  • A sintaxe ${VAR:?mensagem} faz o Compose parar antes de subir qualquer coisa se a variável faltar.
  • O adminer não aparece em docker compose ps sem o perfil: serviço opcional não pesa no dia a dia.
