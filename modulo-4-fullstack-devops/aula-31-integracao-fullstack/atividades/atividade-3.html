Do Build ao Endereço Público

Aula 31 · Módulo 4: Fullstack, DevOps e Projeto Final · ByteClass

O que o build faz com a variável

# .env.development
VITE_API_URL=http://localhost:3000

# .env.production
VITE_API_URL=https://minha-api.onrender.com

Depois de npm run build, procure a URL no bundle gerado:

grep -r "onrender.com" dist/

Ela aparece escrita dentro do JavaScript. Isso significa duas coisas:

  • Trocar de API exige build novo — não basta reiniciar nada.
  • Tudo que tem prefixo VITE_ vai para o navegador do usuário. Nunca coloque segredo ali.

CORS em produção

// Na API, a origem muda quando o frontend sai do localhost:
app.use(cors({
  origin: [
    'http://localhost:5173',
    'https://douglasabnovato.github.io'
  ]
}));

Roteiro de publicação

  1. Publicar a API primeiro e anotar a URL.
  2. Escrever a URL no .env.production do frontend.
  3. Acrescentar a origem do frontend no CORS da API.
  4. npm run build.
  5. Publicar a pasta dist.
  6. Abrir no celular, com dados móveis, e testar o fluxo inteiro.

O teste no celular com dados móveis não é exagero: ele pega erro de CORS, de conteúdo misto (HTTPS chamando HTTP) e de caminho relativo que passam despercebidos no desktop.
