🔌 1. O Contrato entre Frontend e Backend

Antes de escrever o fetch, decidir o contrato: que rota, que formato, que status. Integração quebra muito mais por combinação malfeita do que por código errado.

  • 📄 Usando a Fetch API — MDN O método padrão do navegador para falar com o servidor, com exemplos de cada verbo.
  • 📄 Códigos de Status HTTP — MDN O que o frontend deve fazer em cada faixa de resposta.
  • 📄 OpenAPI Specification O formato padrão para descrever um contrato de API de maneira que máquina e pessoa leiam.
  • 📄 CORS — MDN O erro que aparece na primeira integração local e o que realmente o causa.

🎥 Curadoria de vídeo pendente. Este bloco recebe os vídeos de apoio selecionados pelo instrutor para o tema acima.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: deixe a API da aula 23 rodando em localhost:3000 e crie um projeto React com Vite.
  2. Mapeando as Rotas: escreva num arquivo CONTRATO.md as quatro rotas com método e caminho.
  3. Definindo a Entrada: para cada rota, documente o formato do corpo com um exemplo em JSON.
  4. Definindo a Saída: documente o corpo de resposta de sucesso, com exemplo real copiado da API.
  5. Padronizando o Erro: defina um formato único de erro — { erro: string } — e aplique em todas as rotas.
  6. Listando os Status: registre quais status cada rota pode devolver e o que cada um significa.
  7. Variável de Ambiente: crie .env no frontend com VITE_API_URL=http://localhost:3000.
  8. Camada de Acesso: crie src/api/cliente.js lendo a URL base de import.meta.env.
  9. Primeira Chamada: escreva uma função listarTarefas() que faz o GET e devolve o JSON.
  10. Validação e Testes: chame a função no console do navegador e confirme que o dado chega — e o CORS não bloqueia.

⏳ 2. Os Três Estados de Toda Chamada de Rede

Carregando, erro e sucesso. A maior parte das telas trata só o terceiro, e é por isso que o usuário vê tela branca quando a rede demora e nada quando a API cai.

  • 📄 useEffect — documentação do React Onde a busca de dado acontece e como evitar chamada duplicada e vazamento.
  • 📄 Sincronizando com Efeitos — React O guia oficial sobre efeitos, com a seção de busca de dados e limpeza.
  • 📄 AbortController — MDN Como cancelar uma requisição quando o componente sai da tela.
  • 📄 web.dev — Otimizando o LCP Por que o tempo até a primeira resposta visível define a percepção de qualidade.

🎥 Curadoria de vídeo pendente. Este bloco recebe os vídeos de apoio selecionados pelo instrutor para o tema acima.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie o componente ListaTarefas.jsx no projeto React.
  2. Estrutura de Dados: declare três estados com useState — dados, carregando e erro.
  3. Disparando a Busca: use useEffect com array de dependências vazio para chamar a API na montagem.
  4. Ligando o Carregando: inicie carregando como true e desligue no bloco finally.
  5. Capturando a Falha: no catch, guarde uma mensagem em erro em vez de deixar quebrar.
  6. Diferenciando o Erro: verifique resposta.ok — status 4xx não cai no catch do fetch sozinho.
  7. Renderização Condicional: devolva cedo a tela de carregando e a de erro, antes da lista.
  8. Tela de Vazio: quando a lista vier certa e sem itens, mostre um convite à primeira ação.
  9. Cancelando na Saída: use AbortController e cancele no retorno do useEffect.
  10. Validação e Testes: derrube a API e recarregue a tela; suba de novo e confirme os quatro cenários.
Concluiu todos os passos?

🚀 3. Publicando as Duas Metades

Na máquina tudo funciona. O bloco fecha com o que muda quando a API sai do localhost: URL de produção, variável de ambiente no provedor e o CORS que volta a aparecer.

  • 📄 Vite — Construindo para Produção O que o build gera e como servir os arquivos estáticos resultantes.
  • 📄 Vite — Variáveis de Ambiente e Modos Por que a variável precisa do prefixo VITE_ e em que momento ela é substituída.
  • 📄 GitHub Pages — documentação oficial Como publicar o frontend estático direto do repositório.
  • 📄 Twelve-Factor — Configuração O princípio de que a mesma imagem roda em qualquer ambiente, mudando só a configuração.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: rode npm run build no frontend e observe a pasta dist gerada.
  2. Inspecionando o Build: abra o JS gerado e procure a URL da API — ela foi embutida no arquivo.
  3. Entendendo a Consequência: registre no README que trocar a URL exige um build novo, não só reiniciar.
  4. Servindo Localmente: use npx serve dist e confirme que a aplicação construída funciona.
  5. Publicando a API: suba a API num serviço de sua escolha e anote a URL pública resultante.
  6. Variável de Produção: crie .env.production com a URL pública da API.
  7. Ajustando o CORS: na API, inclua a origem do frontend publicado na configuração de CORS.
  8. Novo Build: rode o build de novo e confirme no arquivo gerado que a URL agora é a de produção.
  9. Publicando o Frontend: envie a pasta dist para o GitHub Pages ou serviço equivalente.
  10. Validação e Testes: abra o endereço público num celular, teste o fluxo completo e confira a aba Rede.
Concluiu todos os passos?
