.github/workflows/ci.yml

# Início: ci.yml — verifica API e frontend a cada push e pull request
name: CI

on: [push, pull_request]

jobs:
  api:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: api
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run lint

  web:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: web
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run build
# Fim de ci.yml

Checklist de setup

  • [ ] Repositório com api/, web/ e docs/ criados e com um commit cada.
  • [ ] .env.example em cada parte, sem nenhum valor real; .env no .gitignore.
  • [ ] docker compose up sobe banco e API, e GET /saude responde 200.
  • [ ] Frontend chama /saude e mostra o resultado na tela.
  • [ ] Esteira verde nos dois jobs.
  • [ ] Regra de proteção da main exigindo pull request e esteira verde.
  • [ ] Issues do MVP no quadro, cada uma com dono e critérios de aceite.
  • [ ] README com os três comandos para subir o projeto, testado por um colega.

O que observar

  • O job do frontend roda o build: erro de importação aparece na esteira, não no dia do deploy.
  • Os dois jobs rodam em paralelo e cada um só olha a própria pasta.
  • O checklist tem item testado por outra pessoa: setup que só funciona para quem fez não está pronto.
