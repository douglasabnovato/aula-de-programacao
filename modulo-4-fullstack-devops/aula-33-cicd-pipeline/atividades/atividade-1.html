Primeira Esteira — .github/workflows/ci.yml

Aula 33 · Módulo 4: Fullstack, DevOps e Projeto Final · ByteClass

O menor workflow útil

name: CI

on:
  push:
    branches: [main, developer]
  pull_request:

jobs:
  verificar:
    runs-on: ubuntu-latest
    steps:
      - name: Baixar o código
        uses: actions/checkout@v4

      - name: Preparar o Node
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Instalar dependências
        run: npm ci

npm ci, não npm install

npm install pode atualizar o package-lock.json e instalar versões diferentes das que você testou. npm ci instala exatamente o que está no lock, falha se houver divergência, e é mais rápido. Numa esteira, é sempre ci.

As três siglas, separadas

  • Integração contínua (CI): todo commit é verificado automaticamente.
  • Entrega contínua (CD): todo commit aprovado fica pronto para publicar — alguém aperta o botão.
  • Implantação contínua (CD): todo commit aprovado é publicado, sem botão.

Muita equipe diz que faz a terceira e faz a primeira. Não tem problema — tem problema chamar de outra coisa.

Prove que a esteira funciona

Uma esteira que nunca ficou vermelha não provou nada. Quebre o código de propósito, faça push, e confirme que ela barra. Só depois disso você pode confiar no verde.
