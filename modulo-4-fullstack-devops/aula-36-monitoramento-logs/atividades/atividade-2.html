Métricas e Health Checks — Código de Referência

Aula 36 · Módulo 4: Fullstack, DevOps e Projeto Final · ByteClass

O que esta atividade entrega

A API expondo /metrics no formato do Prometheus, com contador e histograma por rota, dois health checks e um Prometheus no Compose coletando a cada 15 segundos.

src/metricas.js

// Início: metricas.js — contador de requisições e histograma de duração para o Prometheus
const client = require('prom-client');

const registro = new client.Registry();
client.collectDefaultMetrics({ register: registro });

const requisicoes = new client.Counter({
  name: 'http_requisicoes_total',
  help: 'Total de requisições HTTP recebidas',
  labelNames: ['metodo', 'rota', 'status'],
  registers: [registro]
});

const duracao = new client.Histogram({
  name: 'http_duracao_segundos',
  help: 'Duração das requisições HTTP em segundos',
  labelNames: ['metodo', 'rota', 'status'],
  buckets: [0.05, 0.1, 0.25, 0.5, 1, 2.5],
  registers: [registro]
});

// mede cada requisição quando a resposta termina
function medirRequisicoes(req, res, next) {
  const encerrar = duracao.startTimer();
  res.on('finish', () => {
    const rota = req.route ? req.baseUrl + req.route.path : 'nao_mapeada';
    const rotulos = { metodo: req.method, rota, status: String(res.statusCode) };
    requisicoes.inc(rotulos);
    encerrar(rotulos);
  });
  next();
}

// devolve o texto que o Prometheus coleta
async function rotaMetricas(req, res) {
  res.set('Content-Type', registro.contentType);
  res.end(await registro.metrics());
}

module.exports = { medirRequisicoes, rotaMetricas };
// Fim de metricas.js

src/saude.js

// Início: saude.js — rotas de liveness e readiness
const express = require('express');
const { pool } = require('./db');

const router = express.Router();

// responde se o processo está vivo
router.get('/vivo', (req, res) => {
  res.json({ status: 'vivo' });
});

// responde se a API consegue atender, testando o banco
router.get('/pronto', async (req, res) => {
  try {
    await pool.query('SELECT 1');
    res.json({ status: 'pronto', banco: 'ok' });
  } catch (erro) {
    res.status(503).json({ status: 'indisponivel', banco: erro.message });
  }
});

module.exports = router;
// Fim de saude.js

prometheus.yml

# Início: prometheus.yml — coleta as métricas da API a cada 15 segundos
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: api-agendamentos
    metrics_path: /metrics
    static_configs:
      - targets: ["api:3000"]
# Fim de prometheus.yml

compose.yaml (trecho acrescentado)

# Início: trecho do compose.yaml — serviço do Prometheus ao lado da API
services:
  prometheus:
    image: prom/prometheus
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml:ro
    ports:
      - "9090:9090"
    depends_on:
      - api
# Fim do trecho do compose.yaml

Como rodar

  1. No app.js, registre app.use(medirRequisicoes) antes das rotas, app.get('/metrics', rotaMetricas) e app.use('/saude', require('./src/saude'))
  2. Suba com docker compose up --build
  3. Abra http://localhost:3000/metrics e procure http_requisicoes_total
  4. Abra http://localhost:9090, vá em Status › Targets e confirme o alvo UP
  5. Consulte histogram_quantile(0.95, sum(rate(http_duracao_segundos_bucket[5m])) by (le))

O que observar

  • Cada combinação de rótulos vira uma série: usar o caminho com id cria uma série por registro e sobrecarrega o Prometheus.
  • /saude/vivo não toca no banco; se tocasse, uma queda do banco faria o orquestrador reiniciar uma API que está saudável.
  • O Prometheus busca os dados na API (pull): a API não precisa saber que ele existe.
