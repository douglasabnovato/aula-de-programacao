Dois Serviços na Mesma Rede — Código de Referência

Aula 35 · Módulo 4: Fullstack, DevOps e Projeto Final · ByteClass

O que esta atividade entrega

Dois serviços Express independentes: pedidos, exposto na porta 3000, e notificacoes, acessível só pela rede interna do Compose. Um pedido criado gera uma chamada HTTP ao outro serviço.

notificacoes/server.js

// Início: server.js do serviço de notificações — registra o aviso de cada pedido criado
const express = require('express');

const app = express();
app.use(express.json());

const enviadas = [];

// registra uma notificação de pedido criado
app.post('/notificacoes', (req, res) => {
  const { pedidoId, cliente } = req.body;
  if (!pedidoId || !cliente) {
    return res.status(400).json({ erro: 'pedidoId e cliente são obrigatórios' });
  }
  const notificacao = {
    id: enviadas.length + 1,
    pedidoId,
    cliente,
    canal: 'email',
    enviadaEm: new Date().toISOString()
  };
  enviadas.push(notificacao);
  console.log(`Notificação ${notificacao.id} enviada para ${cliente}`);
  res.status(201).json(notificacao);
});

// lista as notificações já enviadas
app.get('/notificacoes', (req, res) => {
  res.json(enviadas);
});

const porta = process.env.PORT || 4001;
app.listen(porta, () => console.log(`Notificações ouvindo na porta ${porta}`));
// Fim de server.js

pedidos/server.js

// Início: server.js do serviço de pedidos — cria o pedido e avisa o serviço de notificações
const express = require('express');

const app = express();
app.use(express.json());

const NOTIFICACOES_URL = process.env.NOTIFICACOES_URL;
const pedidos = [];

// cria o pedido e chama o serviço de notificações pela rede
app.post('/pedidos', async (req, res) => {
  const { cliente, itens } = req.body;
  if (!cliente || !Array.isArray(itens) || itens.length === 0) {
    return res.status(400).json({ erro: 'cliente e itens são obrigatórios' });
  }
  const pedido = { id: pedidos.length + 1, cliente, itens, criadoEm: new Date().toISOString() };
  pedidos.push(pedido);

  const resposta = await fetch(`${NOTIFICACOES_URL}/notificacoes`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ pedidoId: pedido.id, cliente })
  });
  console.log(`Pedido ${pedido.id} criado; notificações respondeu ${resposta.status}`);
  res.status(201).json(pedido);
});

// lista os pedidos
app.get('/pedidos', (req, res) => {
  res.json(pedidos);
});

const porta = process.env.PORT || 3000;
app.listen(porta, () => console.log(`Pedidos ouvindo na porta ${porta}`));
// Fim de server.js

compose.yaml

# Início: compose.yaml — dois serviços independentes; só pedidos é exposto
services:
  pedidos:
    build: ./pedidos
    environment:
      PORT: 3000
      NOTIFICACOES_URL: http://notificacoes:4001
    ports:
      - "3000:3000"
    depends_on:
      - notificacoes

  notificacoes:
    build: ./notificacoes
    environment:
      PORT: 4001
# Fim de compose.yaml

Como rodar

  1. Em cada pasta, rode npm init -y e npm install express e crie um Dockerfile como o da aula 32
  2. Na raiz, rode docker compose up --build
  3. Crie um pedido: curl -X POST localhost:3000/pedidos -H "Content-Type: application/json" -d '{"cliente":"ana@exemplo.com","itens":["granola"]}'
  4. Veja as notificações por dentro da rede: docker compose exec pedidos wget -qO- http://notificacoes:4001/notificacoes

O que observar

  • localhost:4001 não responde da sua máquina: o serviço de notificações não publicou porta e só existe na rede do projeto.
  • Cada serviço tem seu package.json, sua imagem e pode ser publicado sem mexer no outro.
  • Esta versão ainda não trata falha: se notificações cair, o await fetch derruba a criação do pedido — é o ponto de partida da atividade 2.
