api/migracoes/002_sem_sobreposicao.sql

-- Início: 002_sem_sobreposicao.sql — impede dois agendamentos sobrepostos para a mesma profissional
CREATE EXTENSION IF NOT EXISTS btree_gist;

ALTER TABLE agendamentos
  ADD CONSTRAINT agendamentos_sem_sobreposicao
  EXCLUDE USING gist (
    profissional_id WITH =,
    tstzrange(inicio, fim) WITH &&
  )
  WHERE (status = 'marcado');

CREATE INDEX IF NOT EXISTS idx_agendamentos_inicio ON agendamentos (inicio);
-- Fim de 002_sem_sobreposicao.sql

Definição de Pronto de cada rota

  • [ ] Entrada e saída iguais ao openapi.yaml, campo a campo.
  • [ ] Entrada inválida devolve 400 com o esquema de erro único.
  • [ ] Consulta ao banco com parâmetros ($1, $2), nunca com texto concatenado.
  • [ ] Regra de negócio crítica garantida também no banco.
  • [ ] Pelo menos um teste automatizado do caminho feliz e um do erro principal.
  • [ ] Rota testada manualmente e issue movida para Feito.

O que observar

  • A restrição EXCLUDE faz o banco recusar a sobreposição mesmo com duas requisições chegando juntas; o erro chega à API com o código 23P01, que o middleware traduz para 409.
  • O WHERE (status = 'marcado') libera o horário quando o agendamento é cancelado.
  • O quadro liga cada rota a uma história do escopo: rota sem história é escopo que cresceu sem decisão.
