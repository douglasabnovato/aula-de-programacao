# Ficha de Deploy — Agenda Lírio

## Onde está cada parte
| Parte    | Serviço (plano)        | URL pública                                | Deploy automático |
|----------|------------------------|--------------------------------------------|-------------------|
| Banco    | Neon (free)            | (painel do Neon — não publicar a URL)      | não se aplica     |
| API      | Render Web Service (free) | https://agenda-lirio-api.onrender.com   | push na main      |
| Frontend | Vercel (Hobby)         | https://agenda-lirio.vercel.app            | push na main      |

## Variáveis por parte (nomes, nunca valores)
- API: DATABASE_URL, JWT_SECRET, NODE_ENV=production, ORIGEM_FRONT, LOG_LEVEL=info
- Frontend: VITE_API_URL

## Ordem de publicação
1. Criar o banco e copiar a connection string para o gerenciador de senhas.
2. Rodar `npm run migrar` apontando para o banco de produção.
3. Criar o Web Service da API com build `npm ci`, início `npm start` e health check `/saude/pronto`.
4. Publicar o frontend com VITE_API_URL = URL da API.
5. Atualizar ORIGEM_FRONT da API com a URL do frontend.
6. Rodar `scripts/fumaca.sh`.

## Limites do plano gratuito
- A API hiberna após um período sem tráfego; primeira requisição medida: ___ segundos.
- O banco tem limite de armazenamento e de horas de computação por mês.
- Antes da banca: acessar a API alguns minutos antes para ela estar acordada.

Como usar

  1. Copie para docs/DEPLOY.md e troque as URLs pelas suas
  2. Preencha o tempo medido da primeira requisição após hibernação
  3. Confira que nenhum valor de segredo foi escrito na ficha
  4. Linke a ficha no README

O que observar

  • A ficha lista nomes de variáveis, não valores: ela pode ficar no repositório público.
  • O passo 5 existe porque a URL do frontend só é conhecida depois que ele é publicado.
  • O limite de hibernação vira item da preparação da apresentação: a banca não pode esperar a API acordar.
