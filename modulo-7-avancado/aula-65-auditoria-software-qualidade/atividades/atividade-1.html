Portão de Qualidade com ESLint e GitHub Actions — Código de Referência

Aula 65 · Módulo 7: Avançado (Engenharia e Arquitetura Master) · ByteClass

O que esta atividade entrega

A configuração de lint com limites de complexidade, os scripts de auditoria e o workflow que roda tudo em cada pull request. Combinado com a proteção de branch, impede o merge de código que ultrapassa os limites.

eslint.config.js

// Início: regras de qualidade com limites de complexidade para a API
const js = require('@eslint/js');
const globals = require('globals');

module.exports = [
  js.configs.recommended,
  {
    files: ['src/**/*.js'],
    languageOptions: {
      ecmaVersion: 2023,
      sourceType: 'commonjs',
      globals: globals.node,
    },
    rules: {
      complexity: ['error', 10],
      'max-depth': ['error', 3],
      'max-lines-per-function': ['error', { max: 60, skipBlankLines: true, skipComments: true }],
      'max-params': ['error', 4],
      'no-else-return': 'error',
      eqeqeq: 'error',
    },
  },
];
// Fim de eslint.config.js

package.json (trecho de scripts)

{
  "scripts": {
    "lint": "eslint src",
    "test": "jest --coverage",
    "audit:deps": "npm audit --audit-level=high",
    "audit:qualidade": "npm run lint && npm test && npm run audit:deps"
  }
}

.github/workflows/qualidade.yml

# Início: portão de qualidade executado em todo pull request para a main
name: qualidade
on:
  pull_request:
    branches: [main]
jobs:
  qualidade:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - name: Lint apenas nos arquivos alterados
        run: |
          ARQUIVOS=$(git diff --name-only --diff-filter=ACMR origin/main...HEAD -- 'src/*.js' 'src/**/*.js')
          if [ -n "$ARQUIVOS" ]; then npx eslint $ARQUIVOS; else echo "Nenhum arquivo JS alterado"; fi
      - run: npm test
      - run: npm run audit:deps
# Fim de .github/workflows/qualidade.yml

Como rodar

  1. npm install -D eslint @eslint/js globals jest
  2. Salve os arquivos acima e rode npm run audit:qualidade localmente
  3. Envie o workflow para o GitHub e abra um pull request
  4. Em Settings, Branches, marque o job qualidade como verificação obrigatória da main

O que observar

  • O fetch-depth: 0 é necessário para o git diff enxergar a branch main.
  • Aplicar a regra só nos arquivos alterados permite adotar o portão num projeto legado sem parar o time.
  • O limite 10 de complexidade é um ponto de partida: registre no README por que escolheu cada número.
