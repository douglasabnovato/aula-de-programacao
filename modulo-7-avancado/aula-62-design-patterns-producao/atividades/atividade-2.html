Strategy no lugar do Switch

Aula 62 · Módulo 7: Avançado (Engenharia e Arquitetura Master) · ByteClass

O antes, que todo projeto tem

function calcularFrete(tipo, peso, distancia) {
  switch (tipo) {
    case 'pac':
      return 8 + (peso * 0.5) + (distancia * 0.02);
    case 'sedex':
      return 15 + (peso * 0.9) + (distancia * 0.05);
    case 'expresso':
      if (distancia > 500) throw new Error('Expresso até 500km');
      return 28 + (peso * 1.4) + (distancia * 0.08);
    case 'retirada':
      return 0;
    default:
      throw new Error('Modalidade inválida');
  }
}

Quatro razões para esse arquivo mudar. Acrescentar uma modalidade mexe no mesmo bloco que todas as outras usam — e o teste precisa cobrir tudo de novo.

O depois

// estrategias/pac.js
const pac = {
  nome: 'PAC',
  calcular: ({ peso, distancia }) => 8 + peso * 0.5 + distancia * 0.02
};

// estrategias/expresso.js
const expresso = {
  nome: 'Expresso',
  calcular: ({ peso, distancia }) => {
    if (distancia > 500) throw new Error('Expresso atende até 500km');
    return 28 + peso * 1.4 + distancia * 0.08;
  }
};

// estrategias/index.js
const ESTRATEGIAS = { pac, sedex, expresso, retirada };

function calcularFrete(tipo, dados) {
  const estrategia = ESTRATEGIAS[tipo];
  if (!estrategia) throw new Error(`Modalidade inválida: ${tipo}`);
  return estrategia.calcular(dados);
}

O teste que prova o ganho

test('expresso recusa acima de 500km', () => {
  assert.throws(() => expresso.calcular({ peso: 2, distancia: 600 }));
});

Cada estratégia se testa sozinha, sem tocar nas outras.

Acrescentando a quinta modalidade

# Com switch:      1 arquivo alterado, todos os testes refeitos
# Com strategy:    1 arquivo novo + 1 linha no mapa

Quando NÃO vale trocar o switch

Com dois ou três ramos, e sem previsão de crescer, o switch é mais legível. O padrão compensa a partir de quatro ramos, ou quando os ramos têm lógica de verdade em vez de uma conta só. Strategy com dois casos é indireção sem ganho.

Observer: você já usa desde o primeiro dia

// Isto é Observer:
botao.addEventListener('click', aoClicar);

// E isto também, no Node:
emissor.on('pedido:criado', enviarEmail);
emissor.on('pedido:criado', darBaixaNoEstoque);
emissor.emit('pedido:criado', pedido);

Quem emite não sabe quem escuta, nem quantos são. É o desacoplamento mais forte que existe — e por isso mesmo o mais difícil de depurar: não há como saber, lendo o emissor, o que vai acontecer.
