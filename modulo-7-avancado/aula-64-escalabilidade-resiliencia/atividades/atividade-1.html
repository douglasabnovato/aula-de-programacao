Teste de Carga com k6 — Código de Referência

Aula 64 · Módulo 7: Avançado (Engenharia e Arquitetura Master) · ByteClass

O que esta atividade entrega

Um script k6 com rampa de usuários, verificações por requisição e metas de latência e erro que reprovam o teste automaticamente. Serve para medir a API antes e depois de cada ajuste de capacidade.

carga/listagem.js

// Início: teste de carga da rota de listagem com rampa e metas de serviço
import http from 'k6/http';
import { check, sleep } from 'k6';

const BASE_URL = __ENV.BASE_URL || 'http://localhost:3000';

export const options = {
  stages: [
    { duration: '1m', target: 50 },
    { duration: '1m', target: 100 },
    { duration: '1m', target: 200 },
    { duration: '1m', target: 200 },
    { duration: '30s', target: 0 },
  ],
  thresholds: {
    http_req_duration: ['p(95)<400'],
    http_req_failed: ['rate<0.01'],
    checks: ['rate>0.99'],
  },
};

// Cada usuário virtual lista produtos, confere a resposta e espera como uma pessoa real
export default function () {
  const res = http.get(`${BASE_URL}/produtos?pagina=1`, { tags: { rota: 'listagem' } });
  check(res, {
    'status 200': (r) => r.status === 200,
    'corpo é uma lista': (r) => Array.isArray(r.json('dados')),
  });
  sleep(Math.random() * 2 + 1);
}

// Resumo final impresso no terminal com os números que vão para o README
export function handleSummary(data) {
  const p95 = data.metrics.http_req_duration.values['p(95)'].toFixed(0);
  const erros = (data.metrics.http_req_failed.values.rate * 100).toFixed(2);
  return { stdout: `\np95: ${p95} ms | erros: ${erros}%\n` };
}
// Fim de carga/listagem.js

docker-compose.yml

# Início: API e banco para o teste de carga, com o tamanho do pool vindo do ambiente
services:
  api:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://app:app@db:5432/loja
      DB_POOL_MAX: "10"
    depends_on:
      - db
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
      POSTGRES_DB: loja
# Fim de docker-compose.yml

Como rodar

  1. docker compose up -d --build
  2. Instale o k6 conforme a documentação oficial
  3. k6 run carga/listagem.js
  4. Repita com DB_POOL_MAX=2 no compose e compare o resumo

O que observar

  • Com o pool em 2, a latência sobe antes de aparecer erro: a fila de espera por conexão é o primeiro sintoma.
  • O sleep aleatório evita que todos os usuários virtuais batam no mesmo instante, o que distorceria a medição.
  • O código de saída do k6 muda quando um threshold falha, o que permite usar o script como etapa de CI.
