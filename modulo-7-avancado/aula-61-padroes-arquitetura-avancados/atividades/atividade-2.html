Hexagonal: Portas, Adaptadores e o Teste sem Infra

Aula 61 · Módulo 7: Avançado (Engenharia e Arquitetura Master) · ByteClass

O desenho

        ┌─────────── adaptadores de entrada ───────────┐
        │   HTTP        CLI         Fila de mensagens  │
        └──────┬──────────┬──────────────┬─────────────┘
               ↓          ↓              ↓
        ┌───── portas de entrada (casos de uso) ───────┐
        │                                              │
        │              DOMÍNIO                         │
        │   (entidades e regras — nada de framework)   │
        │                                              │
        └───── portas de saída (interfaces) ───────────┘
               ↓          ↓              ↓
        ┌──────┴──────────┴──────────────┴─────────────┐
        │  Postgres     E-mail        Armazenamento    │
        └────────── adaptadores de saída ──────────────┘

As setas entram e saem do domínio, mas o domínio não conhece ninguém de fora: ele define as portas, e os adaptadores as implementam.

A porta, definida pelo domínio

// core/ports/RepositorioDePedidos.js
// Contrato. Quem implementa é a borda; quem define é o domínio.
class RepositorioDePedidos {
  salvar(pedido)      { throw new Error('não implementado'); }
  buscarPorId(id)     { throw new Error('não implementado'); }
  buscarPendentes()   { throw new Error('não implementado'); }
}

module.exports = RepositorioDePedidos;

Dois adaptadores para a mesma porta

// infra/PedidosEmMemoria.js — usado em teste
class PedidosEmMemoria extends RepositorioDePedidos {
  constructor() { super(); this.itens = []; }
  salvar(p)     { this.itens.push(p); return p; }
  buscarPorId(id) { return this.itens.find(p => p.id === id); }
  buscarPendentes() { return this.itens.filter(p => !p.pago); }
}

// infra/PedidosPostgres.js — usado em produção
class PedidosPostgres extends RepositorioDePedidos {
  constructor(conexao) { super(); this.db = conexao; }
  async salvar(p) { /* INSERT ... */ }
  async buscarPorId(id) { /* SELECT ... */ }
  async buscarPendentes() { /* SELECT ... WHERE pago = false */ }
}

O ganho concreto: teste em milissegundos

const { test } = require('node:test');
const assert = require('node:assert');

test('pedido sem itens não pode ser fechado', () => {
  const repo = new PedidosEmMemoria();       // sem banco, sem Docker
  const caso = new FecharPedido(repo);

  assert.throws(() => caso.executar({ itens: [] }));
});

Sem subir Postgres, sem seed, sem limpar tabela entre testes. O teste roda em milissegundos e testa exatamente a regra de negócio — que é o que importa.

A verificação automática

grep -rE "require\('(express|pg|mongoose|axios)'\)" src/core/

Deve voltar vazio. Vale colocar como passo na esteira de CI: se alguém importar framework no domínio, a esteira barra.
