# Modelo de Ameaças — Consulta Já

## 1. O que estamos construindo
Paciente envia exame (PDF) pelo app; médico parceiro vê exames dos seus pacientes; admin gerencia médicos.

## 2. Fluxos que cruzam fronteira de confiança
| Nº | Origem → Destino | Dado |
|----|------------------|------|
| F1 | App (internet) → API | login, token |
| F2 | App → API → Storage | arquivo do exame |
| F3 | API → Banco | dados do paciente |
| F4 | Médico (internet) → API | listagem e download de exames |
| F5 | Laboratório parceiro → Webhook | resultado de exame |

## 3. Ameaças (STRIDE) e risco (probabilidade × impacto, 1 a 3)
| ID | Fluxo | Categoria | Ameaça | P | I | Risco |
|----|-------|-----------|--------|---|---|-------|
| A1 | F4 | Vazamento | Médico troca o id na URL e baixa exame de paciente de outro médico | 3 | 3 | 9 |
| A2 | F5 | Falsificação | Qualquer pessoa chama o webhook e injeta resultado falso | 2 | 3 | 6 |
| A3 | F2 | Adulteração | Upload de arquivo que não é PDF, com script embutido | 2 | 3 | 6 |
| A4 | F1 | Negação de serviço | Força bruta no login bloqueia contas legítimas | 3 | 2 | 6 |
| A5 | F4 | Repúdio | Médico nega ter acessado um exame e não há registro | 2 | 2 | 4 |
| A6 | F1 | Elevação de privilégio | Campo `papel` aceito no cadastro permite virar admin | 1 | 3 | 3 |

## 4. Mitigações das cinco primeiras
| ID | Defesa | Requisito ASVS | Responsável |
|----|--------|----------------|-------------|
| A1 | Filtrar por vínculo médico-paciente em toda consulta; teste automatizado de IDOR | Controle de acesso | Time API |
| A2 | Assinatura HMAC no webhook com segredo por parceiro e janela de tempo | Comunicação segura | Time Integrações |
| A3 | Validar tipo pelo conteúdo, limitar tamanho, servir com `Content-Disposition: attachment` | Arquivos | Time API |
| A4 | Rate limit por IP e por conta, atraso progressivo em vez de bloqueio total | Autenticação | Time API |
| A5 | Log de auditoria imutável de cada download com usuário, exame e horário | Logs | Time Plataforma |

## 5. Revisão
Refazer este modelo a cada nova integração externa ou novo tipo de usuário.

Como usar

  1. Copie a estrutura para docs/seguranca/ do seu projeto
  2. Substitua os fluxos pelos do seu diagrama
  3. Preencha a tabela STRIDE só para fluxos que cruzam fronteira
  4. Transforme cada mitigação em issue com critério de aceite

O que observar

  • Toda ameaça aponta um fluxo numerado: sem diagrama, a lista vira opinião genérica.
  • A1 tem risco máximo e é exatamente o IDOR explorado no tema seguinte.
  • O documento tem versão e gatilho de revisão; um modelo que não é atualizado envelhece junto com o sistema.
