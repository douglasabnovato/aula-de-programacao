Pipeline de Segurança com GitHub Actions — Código de Referência

Aula 66 · Módulo 7: Avançado (Engenharia e Arquitetura Master) · ByteClass

O que esta atividade entrega

Um workflow com três camadas de verificação (segredos, dependências e análise estática) e a configuração do Dependabot. Nenhum segredo real aparece no repositório: tudo que é sensível vem de process.env ou dos secrets do GitHub.

.github/workflows/secops.yml

# Início: verificações de segurança executadas em todo push e pull request
name: secops
on:
  push:
    branches: [main]
  pull_request:
  schedule:
    - cron: '0 6 * * 1'
permissions:
  contents: read
jobs:
  segredos:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: gitleaks/gitleaks-action@v2
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  dependencias:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm audit --audit-level=high --omit=dev
  codeql:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
    steps:
      - uses: actions/checkout@v4
      - uses: github/codeql-action/init@v3
        with:
          languages: javascript
      - uses: github/codeql-action/analyze@v3
# Fim de .github/workflows/secops.yml

.github/dependabot.yml

# Início: atualização semanal de dependências npm e de actions
version: 2
updates:
  - package-ecosystem: npm
    directory: /
    schedule:
      interval: weekly
    open-pull-requests-limit: 5
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
# Fim de .github/dependabot.yml

src/config.js

// Início: leitura centralizada de segredos, falhando cedo se algum faltar
const OBRIGATORIAS = ['DATABASE_URL', 'JWT_SECRET', 'PAGAMENTO_API_KEY'];

// Confere as variáveis obrigatórias e devolve a configuração da aplicação
function carregarConfig() {
  const faltando = OBRIGATORIAS.filter((nome) => !process.env[nome]);
  if (faltando.length) throw new Error(`Variáveis de ambiente ausentes: ${faltando.join(', ')}`);
  return {
    databaseUrl: process.env.DATABASE_URL,
    jwtSecret: process.env.JWT_SECRET,
    pagamentoApiKey: process.env.PAGAMENTO_API_KEY,
  };
}

module.exports = { carregarConfig };
// Fim de src/config.js

Como rodar

  1. Salve os arquivos e envie para o GitHub
  2. Numa branch de teste, faça commit de um arquivo com chave falsa e abra um PR: o job segredos falha
  3. Instale uma versão antiga de pacote vulnerável e veja o job dependencias falhar
  4. Acompanhe os alertas do CodeQL na aba Security do repositório

O que observar

  • O gitleaks varre o histórico inteiro: apagar o arquivo num commit novo não esconde a chave, por isso ela precisa ser revogada.
  • O bloco permissions no topo dá só leitura; o job do CodeQL recebe escrita de eventos de segurança porque precisa publicar o resultado.
  • O agendamento semanal pega vulnerabilidades novas em dependências que não mudaram, o que um pipeline só de PR não perceberia.
