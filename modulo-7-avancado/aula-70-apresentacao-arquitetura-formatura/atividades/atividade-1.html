# Arquitetura — Saúde Perto

## 1. Objetivos
- Pacientes de cidades pequenas marcam e fazem teleconsulta sem instalar aplicativo.
- Médicos veem o histórico do paciente antes da consulta.
- A clínica recebe o pagamento no ato do agendamento.

## 2. Atributos de qualidade prioritários
| Atributo | Cenário mensurável |
|----------|--------------------|
| Disponibilidade | 99,5% das tentativas de agendamento bem-sucedidas em 28 dias |
| Segurança | Nenhum médico acessa exame de paciente que não é seu (teste automatizado de IDOR) |
| Desempenho | p95 da busca de horários abaixo de 400 ms com 300 usuários simultâneos |

## 3. Contexto (C4 nível 1)
```mermaid
flowchart LR
  paciente([Paciente]) --> sp[Saúde Perto]
  medico([Médico]) --> sp
  sp --> pag[Gateway de pagamento]
  sp --> video[Serviço de vídeo]
  sp --> email[Serviço de e-mail]
```

## 4. Contêineres (C4 nível 2)
```mermaid
flowchart LR
  web[Web app React] -->|HTTPS/JSON| api[API Node/Express]
  api -->|SQL| db[(PostgreSQL)]
  api -->|publica eventos| fila[[Fila de mensagens]]
  fila --> worker[Worker de notificações]
  worker --> email[Serviço de e-mail]
  api -->|HTTPS com timeout e circuit breaker| pag[Gateway de pagamento]
```

## 5. Fluxo crítico: agendar consulta
1. Web chama `GET /horarios` na API.
2. API consulta o PostgreSQL com índice por médico e data.
3. Web envia `POST /agendamentos` com chave de idempotência.
4. API cobra no gateway com timeout de 2 s e retry com jitter.
5. API grava o agendamento e publica `agendamento.criado` na fila.
6. Worker envia a confirmação por e-mail.

## 6. Decisões
- ADR 001 — Monolito modular em vez de microsserviços
- ADR 002 — Fila para notificações, fora do caminho da requisição
- ADR 003 — Circuit breaker no gateway com agendamento pendente como alternativa

## 7. Riscos e dívidas
| Risco | Mitigação | Aceito? |
|-------|-----------|---------|
| Gateway fora do ar no pico | Circuit breaker e confirmação posterior | Sim, com alerta |
| Banco único sem réplica | Backup diário com restauração testada | Sim, até 5 mil consultas/mês |

## 8. Glossário
**Agendamento pendente:** reserva de horário aguardando confirmação do pagamento, válida por 15 minutos.

Como usar

  1. Copie o arquivo para docs/arquitetura.md do seu projeto
  2. Substitua os objetivos e cenários pelos seus, sempre com número
  3. Ajuste os diagramas Mermaid; o GitHub renderiza os blocos mermaid automaticamente
  4. Crie um arquivo em docs/adr/ para cada decisão listada na seção 6

O que observar

  • Cada atributo de qualidade tem um cenário que pode ser testado, e não um adjetivo como 'rápido' ou 'seguro'.
  • Os dois diagramas têm níveis de zoom diferentes e não misturam contêiner com classe ou tela.
  • O fluxo crítico retoma as práticas do módulo: índice, idempotência, timeout, retry, fila e circuit breaker.
