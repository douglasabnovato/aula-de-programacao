Cálculo de SLI e Orçamento de Erro — Código de Referência

Aula 67 · Módulo 7: Avançado (Engenharia e Arquitetura Master) · ByteClass

O que esta atividade entrega

Um script que lê logs estruturados de requisições, calcula os SLIs de disponibilidade e latência e mostra quanto do orçamento de erro foi consumido, junto com a definição dos SLOs em arquivo versionado.

slo.yaml

# Início: definição dos SLOs da jornada de busca de horários do Vai de Van
servico: api-vai-de-van
jornada: buscar-horarios
rotas:
  - GET /linhas
  - GET /linhas/:id/horarios
janela_dias: 28
slos:
  - nome: disponibilidade
    sli: requisições com status < 500 / total
    meta: 0.995
  - nome: latencia
    sli: requisições com duração < 300 ms / total
    meta: 0.95
politica_orcamento:
  "50%": avisar no canal do time e revisar os deploys da semana
  "75%": congelar lançamentos de risco, só correções e melhorias de confiabilidade
  "100%": congelar lançamentos até o SLI voltar acima da meta por 7 dias
# Fim de slo.yaml

scripts/slo.js

// Início: calcula SLIs e consumo do orçamento de erro a partir de logs JSON por linha
const fs = require('fs');
const readline = require('readline');

const ARQUIVO = process.argv[2] || 'logs/requisicoes.jsonl';
const ROTAS = [/^\/linhas$/, /^\/linhas\/[^/]+\/horarios$/];
const METAS = { disponibilidade: 0.995, latencia: 0.95 };
const LIMITE_LATENCIA_MS = 300;

// Indica se a linha de log pertence à jornada medida
function pertenceAJornada(registro) {
  return registro.method === 'GET' && ROTAS.some((rota) => rota.test(registro.path));
}

// Calcula o SLI e o percentual do orçamento consumido para uma meta
function avaliar(bons, total, meta) {
  const sli = total ? bons / total : 1;
  const permitidos = total * (1 - meta);
  const ruins = total - bons;
  const consumido = permitidos ? (ruins / permitidos) * 100 : 0;
  return { sli: +(sli * 100).toFixed(3), ruins, permitidos: Math.floor(permitidos), orcamentoConsumido: +consumido.toFixed(1) };
}

// Lê o arquivo linha a linha e imprime o relatório
async function main() {
  const leitor = readline.createInterface({ input: fs.createReadStream(ARQUIVO) });
  let total = 0;
  let disponiveis = 0;
  let rapidas = 0;
  for await (const linha of leitor) {
    if (!linha.trim()) continue;
    const registro = JSON.parse(linha);
    if (!pertenceAJornada(registro)) continue;
    total += 1;
    if (registro.status < 500) disponiveis += 1;
    if (registro.durationMs < LIMITE_LATENCIA_MS) rapidas += 1;
  }
  console.table({
    disponibilidade: avaliar(disponiveis, total, METAS.disponibilidade),
    latencia: avaliar(rapidas, total, METAS.latencia),
  });
}

main();
// Fim de scripts/slo.js

Como rodar

  1. Gere tráfego com o k6 e salve os logs em logs/requisicoes.jsonl, um JSON por linha com method, path, status e durationMs
  2. node scripts/slo.js logs/requisicoes.jsonl
  3. Pare o banco por um minuto durante uma nova carga e rode o script de novo
  4. Compare o orcamentoConsumido das duas execuções

O que observar

  • O SLI só conta as rotas da jornada: um erro no painel administrativo não consome o orçamento do passageiro.
  • Um minuto de queda com tráfego alto pode consumir uma fatia grande do orçamento de 28 dias, o que torna o custo da instabilidade visível.
  • A política está versionada ao lado do SLO: a decisão de congelar lançamentos foi combinada antes do problema, não durante.
