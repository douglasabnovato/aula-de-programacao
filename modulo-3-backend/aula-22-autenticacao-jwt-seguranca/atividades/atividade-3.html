CORS, Helmet e Rate Limit — Código de Referência

Aula 22 · Módulo 3: Backend e Banco de Dados · ByteClass

O ponto da atividade

Três linhas de configuração fecham a maior parte das portas que ficam abertas por padrão numa API Express.

app.js — a ordem importa

const express = require('express');
const cors = require('cors');
const helmet = require('helmet');
const rateLimit = require('express-rate-limit');

const app = express();

app.use(helmet());
app.use(cors({ origin: process.env.ORIGEM_PERMITIDA }));
app.use(express.json({ limit: '10kb' }));

const limitadorLogin = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 5,
  message: { erro: 'Muitas tentativas. Tente novamente em 15 minutos.' },
  standardHeaders: true
});

app.use('/auth/login', limitadorLogin);

Por que não usar o curinga no CORS

// Faz o erro sumir, e abre a API para qualquer site:
app.use(cors());

// Diz exatamente quem pode chamar:
app.use(cors({ origin: 'https://meuapp.com.br' }));

O curinga é o atalho que todo mundo usa para parar o erro vermelho no console — e que ninguém volta para arrumar depois.

Checklist antes de publicar

  • O .env está no .gitignore?
  • Alguma resposta de erro vaza stack trace?
  • O token tem expiração?
  • A origem do CORS é específica?
  • O login tem limite de tentativa?
