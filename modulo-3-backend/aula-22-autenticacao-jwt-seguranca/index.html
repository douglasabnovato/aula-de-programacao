🔑 1. Autenticação, Autorização e Senha em Repouso

Duas palavras que parecem sinônimo e não são: autenticar é saber quem é; autorizar é saber o que essa pessoa pode. E antes das duas vem a pergunta que derruba projeto: como a senha está guardada.

  • 📄 OWASP — Authentication Cheat Sheet A referência mais prática sobre o que fazer e o que nunca fazer em autenticação.
  • 📄 OWASP — Password Storage Cheat Sheet Qual algoritmo usar para guardar senha e por que MD5 e SHA não servem.
  • 📄 Autenticação HTTP — MDN Como o cabeçalho Authorization funciona e o que o navegador faz com ele.
  • 📄 Módulo Crypto do Node O que o Node oferece de forma nativa para hash e geração de valores aleatórios seguros.

🎥 Curadoria de vídeo pendente. Este bloco recebe os vídeos de apoio selecionados pelo instrutor para o tema acima.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: na API da aula 21, instale npm install bcryptjs.
  2. Estrutura de Dados: crie um array usuarios no serviço, guardando email e senhaHash.
  3. Rota de Cadastro: crie POST /auth/registrar recebendo email e senha no corpo.
  4. Validação de Entrada: recuse email sem @ e senha com menos de 8 caracteres, com status 400.
  5. Gerando o Hash: use bcrypt.hash(senha, 10) e guarde apenas o resultado — nunca a senha original.
  6. Evitando Duplicidade: se o email já existir, responda 409 em vez de sobrescrever.
  7. Rota de Login: crie POST /auth/login buscando o usuário pelo email.
  8. Comparação Segura: use bcrypt.compare(senha, senhaHash) em vez de comparar strings.
  9. Mensagem Genérica: para email inexistente e senha errada, devolva a mesma resposta 401.
  10. Validação e Testes: cadastre, faça login certo e errado, e confirme no console que a senha em texto puro nunca foi armazenada.
Concluiu todos os passos?

🎫 2. JSON Web Token: Emissão e Verificação

O token resolve o problema de o servidor não precisar lembrar de ninguém. Mas ele é assinado, não escondido: o que você põe dentro, qualquer um lê.

  • 📄 JWT — Introdução Oficial As três partes do token explicadas com exemplo visual e decodificação ao vivo.
  • 📄 RFC 7519 — a especificação do JWT O documento normativo: claims registradas, formato e regras de validação.
  • 📄 OWASP — Riscos comuns com JWT Os erros clássicos: algoritmo none, chave fraca e token sem expiração.
  • 📄 Middlewares no Express Onde o verificador de token entra no ciclo da requisição.

🎥 Curadoria de vídeo pendente. Este bloco recebe os vídeos de apoio selecionados pelo instrutor para o tema acima.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: instale npm install jsonwebtoken e crie JWT_SECRET no .env.
  2. Gerando a Chave: use node -e "console.log(require('crypto').randomBytes(32).toString('hex'))" como segredo.
  3. Emitindo no Login: após validar a senha, chame jwt.sign({ sub: usuario.id }, process.env.JWT_SECRET).
  4. Definindo a Expiração: acrescente { expiresIn: '1h' } como terceiro argumento.
  5. Devolvendo o Token: responda 200 com o token no corpo, nunca na URL.
  6. Inspecionando o Payload: cole o token em jwt.io e confirme que o conteúdo é legível — por isso não se põe senha ali.
  7. Middleware de Proteção: crie auth.middleware.js que lê Authorization: Bearer <token>.
  8. Verificando a Assinatura: use jwt.verify dentro de try/catch e responda 401 na falha.
  9. Anexando o Usuário: coloque o id decodificado em req.usuarioId e chame proximo().
  10. Validação e Testes: chame a rota protegida sem token, com token inválido e com token válido, conferindo os três status.
Concluiu todos os passos?

🛡️ 3. Superfície de Ataque: CORS, Injeção e Rate Limit

Com a autenticação de pé, sobram as portas que ninguém fechou: origem liberada para todo mundo, entrada concatenada direto na consulta e login sem limite de tentativa.

  • 📄 OWASP Top 10 As dez categorias de falha mais comuns em aplicações web, atualizadas pela comunidade.
  • 📄 CORS — MDN Como a política de mesma origem funciona e o que cada cabeçalho de CORS libera.
  • 📄 OWASP — Prevenção de Injeção Consulta parametrizada e validação de entrada como defesa principal.
  • 📄 Helmet — cabeçalhos de segurança no Express O que cada cabeçalho que ele adiciona protege, em uma página curta.

🎥 Curadoria de vídeo pendente. Este bloco recebe os vídeos de apoio selecionados pelo instrutor para o tema acima.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: instale npm install cors helmet express-rate-limit.
  2. Diagnóstico Inicial: chame sua API de um HTML em outra porta e observe o erro de CORS no console do navegador.
  3. Liberando o Necessário: registre app.use(cors({ origin: 'http://localhost:5500' })) — uma origem, não o curinga.
  4. Cabeçalhos de Defesa: registre app.use(helmet()) e compare os cabeçalhos antes e depois na aba Rede.
  5. Limite de Requisição: aplique rateLimit só na rota de login, com 5 tentativas a cada 15 minutos.
  6. Testando o Limite: erre a senha seis vezes seguidas e confirme o status 429 na sexta.
  7. Validação de Tipo: garanta que o corpo recebido é objeto e que os campos são string antes de usar.
  8. Limite de Tamanho: configure express.json({ limit: '10kb' }) para recusar corpo gigante.
  9. Mensagem de Erro Sóbria: remova qualquer stack trace da resposta em produção, deixando-a só no log.
  10. Validação e Testes: refaça os testes das práticas 1 e 2 e confirme que nada quebrou com as defesas ligadas.
Concluiu todos os passos?
