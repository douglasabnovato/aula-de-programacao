Esquema Relacional no Supabase — Código de Referência

Aula 25 · Módulo 3: Backend e Banco de Dados · ByteClass

O que esta atividade entrega

O script SQL completo das tabelas projetos e tarefas, com chave estrangeira em cascata, regra de título no banco, índice e dados de exemplo. Cole no SQL Editor do Supabase e execute.

db/schema.sql

-- Início: esquema relacional de projetos e tarefas para o Postgres do Supabase
create table projetos (
  id bigint generated always as identity primary key,
  nome text not null unique
);

create table tarefas (
  id bigint generated always as identity primary key,
  projeto_id bigint not null references projetos(id) on delete cascade,
  titulo text not null check (char_length(trim(titulo)) > 0),
  feita boolean not null default false,
  criada_em timestamptz not null default now()
);

create index tarefas_projeto_id_idx on tarefas (projeto_id);

insert into projetos (nome) values ('Turma de Inglês A1'), ('Turma de Espanhol B1');

insert into tarefas (projeto_id, titulo) values
  (1, 'Corrigir redações da semana'),
  (1, 'Preparar lista de verbos irregulares'),
  (2, 'Montar roteiro de conversação'),
  (2, 'Enviar calendário de provas');

select t.id, t.titulo, p.nome as projeto
from tarefas t
join projetos p on p.id = t.projeto_id
order by t.id;
-- Fim de schema.sql

Como rodar

  1. Crie um projeto no plano gratuito do Supabase
  2. Abra SQL Editor → New query
  3. Cole o script e clique em Run
  4. Confira as tabelas em Table Editor

O que observar

  • generated always as identity deixa o banco gerar o id — o problema do tarefas.length + 1 da aula 21 some aqui.
  • O check repete a regra da entidade: se um dia outro sistema gravar direto no banco, a regra continua valendo.
  • O Postgres não cria índice sozinho na coluna da chave estrangeira; por isso o create index é explícito.
