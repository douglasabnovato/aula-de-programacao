Row Level Security — Código de Referência

Aula 25 · Módulo 3: Backend e Banco de Dados · ByteClass

O que esta atividade entrega

As políticas que limitam cada usuário às próprias tarefas e um script que entra como um usuário real, com a chave publicável, e mostra o que ele consegue ver e gravar.

db/rls.sql

-- Início: dono por tarefa e políticas de Row Level Security
alter table tarefas add column dono_id uuid references auth.users(id);

alter table tarefas enable row level security;

create policy "dono le as suas"
on tarefas for select
to authenticated
using ((select auth.uid()) = dono_id);

create policy "dono cria as suas"
on tarefas for insert
to authenticated
with check ((select auth.uid()) = dono_id);

create policy "dono altera as suas"
on tarefas for update
to authenticated
using ((select auth.uid()) = dono_id)
with check ((select auth.uid()) = dono_id);

create policy "dono remove as suas"
on tarefas for delete
to authenticated
using ((select auth.uid()) = dono_id);
-- Fim de rls.sql

scripts/testar-rls.js

// Início: script que entra como um usuário e mostra o que o RLS deixa ele ver
require('dotenv').config();
const { createClient } = require('@supabase/supabase-js');

// autentica com e-mail e senha e lista as tarefas visíveis para esse usuário
async function verComo(email, senha) {
  const cliente = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_PUBLISHABLE_KEY);
  const { data: sessao, error: erroLogin } = await cliente.auth.signInWithPassword({ email, password: senha });
  if (erroLogin) throw erroLogin;

  const { data, error } = await cliente.from('tarefas').select('id, titulo, dono_id');
  if (error) throw error;
  console.log(`${email} enxerga ${data.length} tarefa(s):`, data.map((t) => t.titulo));

  const invasao = await cliente
    .from('tarefas')
    .insert({ titulo: 'Tentativa indevida', projeto_id: 1, dono_id: process.env.ID_OUTRO_USUARIO });
  console.log('Inserir em nome de outro:', invasao.error ? invasao.error.message : 'aceito (política faltando!)');

  return sessao.user.id;
}

// roda o teste para o usuário configurado no .env
async function principal() {
  await verComo(process.env.EMAIL_TESTE, process.env.SENHA_TESTE);
}

principal().catch((erro) => {
  console.error('Falhou:', erro.message);
  process.exit(1);
});
// Fim de testar-rls.js

Como rodar

  1. Execute db/rls.sql no SQL Editor
  2. Crie dois usuários em Authentication → Users e atribua uma tarefa a cada um pelo dono_id
  3. Preencha no .env: SUPABASE_PUBLISHABLE_KEY, EMAIL_TESTE, SENHA_TESTE e ID_OUTRO_USUARIO
  4. node scripts/testar-rls.js

O que observar

  • Com RLS ligado e sem política, a consulta devolve lista vazia, não erro: negar por padrão é o comportamento seguro.
  • using filtra o que se lê; with check valida o que se grava — o insert em nome de outro usuário esbarra no segundo.
  • (select auth.uid()) entre parênteses é avaliado uma vez por consulta, e não uma vez por linha.
