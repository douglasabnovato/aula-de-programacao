🧭 1. Escopo, Contrato e Arquitetura do Projeto

🎯 Desafio

A cooperativa fictícia Colheita Viva precisa de uma API para registrar entregas dos produtores, com login, foto do produto e aviso em tempo real para o galpão. O prazo é de duas semanas e o time é você. Como decidir o que entra, o que fica para depois e desenhar a API antes de escrever a primeira rota?

Projeto final não é juntar tudo o que foi visto; é escolher. Esta etapa fixa o problema, o escopo mínimo, o contrato OpenAPI e o modelo de dados antes do código, porque mudar um desenho custa minutos e mudar código pronto custa dias.

  • 📄 The OpenAPI Specification Explained — OpenAPI Initiative Guia do contrato que você escreve antes do código, parte por parte.
  • 📄 Database — Supabase Docs O que o banco do projeto oferece e onde cada recurso é configurado.
  • 📄 OWASP API Security Top 10 (2023) A lista de riscos para revisar o escopo antes de construir.
  • 📄 About READMEs — GitHub Docs O que o README do repositório precisa comunicar a quem chega pela primeira vez.
🎥 Vídeos de apoio

  • ▶️ API REST na Prática — O Que É e Como Funciona? (Explicado com Projeto!) Hashtag Dev · 18:17 — Explica o que é uma API REST e como ela se organiza, com um projeto de exemplo.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie o repositório projeto-final-backend com README.md, .gitignore e .env.example.
  2. Problema em Uma Frase: escreva quem usa, o que precisa e por que hoje não funciona — sem citar tecnologia.
  3. Escopo Mínimo: liste no máximo seis rotas obrigatórias e mova o restante para uma seção Depois da entrega.
  4. Modelo de Dados: desenhe tabelas, chaves e relações em db/schema.sql, como na aula 25.
  5. Contrato Primeiro: escreva docs/openapi.yaml com todas as rotas do escopo, incluindo as respostas de erro.
  6. Erro Provocado: escreva o exemplo de resposta de cada rota e procure uma que dependa de campo ou tabela que não está no modelo; registre o furo e corrija o modelo.
  7. Camadas: decida quais camadas da aula 23 o projeto usa e justifique cada uma em uma linha.
  8. Riscos: aponte, pela lista OWASP API Top 10, os três riscos mais prováveis do seu projeto e a defesa de cada um.
  9. Plano de Entrega: crie uma issue no GitHub por etapa, com critério de pronto.
  10. Validação e Testes: apresente o documento ao instrutor, ajuste o escopo com o retorno e registre no README a versão aprovada.
Concluiu todos os passos?

🏗️ 2. Construção, Qualidade e Deploy Gratuito

🎯 Desafio

A API da Colheita Viva roda na máquina do desenvolvedor, mas a banca vai acessá-la pelo celular, de outra cidade, no dia da apresentação. O que não estiver publicado, testado e documentado não existe para quem avalia. Como chegar ao dia com a API no ar e a prova de que ela funciona?

Construir é repetir o ciclo do módulo em ordem: esquema, caso de uso, repositório, teste. O deploy numa hospedagem gratuita fecha a entrega, com as variáveis cadastradas no painel do serviço e nunca no repositório.

  • 📄 Deploy a Node Express App — Render Docs O passo a passo oficial para publicar uma API Express a partir do GitHub.
  • 📄 Your First Render Deploy — Render Docs Conta, conexão com o repositório e primeiro serviço no ar.
  • 📄 The Practical Test Pyramid — Martin Fowler Para decidir quantos testes de cada tipo o projeto final precisa.
  • 📄 Auditing package dependencies — npm Docs A checagem de dependências que entra no checklist antes do deploy.
🎥 Vídeos de apoio

  • ▶️ Como Hospedar seu Servidor Node gratis no Render Fernando Leonid · 5:32 — Mostra como hospedar um servidor Node.js gratuitamente no Render.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: proteja a branch main e trabalhe com uma branch por issue, integrando por pull request.
  2. Ordem de Construção: para cada rota, siga: esquema Zod, caso de uso, repositório Supabase e teste Supertest — nessa ordem.
  3. Middlewares Globais: monte a cadeia: request id, log, CORS por lista, helmet, rate limit e erro em Problem Details.
  4. Testes: garanta que npm test cobre o caminho feliz e pelo menos um erro de cada rota.
  5. Auditoria: rode npm run seguranca e resolva tudo que for de gravidade alta.
  6. Porta do Ambiente: confirme que a API lê process.env.PORT: quem define a porta em produção é a hospedagem.
  7. Deploy: crie um Web Service no plano gratuito do Render ligado ao repositório, com build npm install e start node server.js.
  8. Erro Provocado: publique sem cadastrar as variáveis no painel e leia no log do Render a recusa da validação de ambiente da aula 29; cadastre e publique de novo.
  9. Pós-Deploy: atualize servers no OpenAPI com a URL pública e confira /docs no ar.
  10. Validação e Testes: rode a coleção de chamadas contra a URL pública e registre no README o link, o status de cada rota e a limitação do plano gratuito: a instância hiberna sem uso e demora a responder na primeira chamada.

🎤 3. Apresentação e Defesa Técnica

🎯 Desafio

Na banca da Colheita Viva, o avaliador pergunta: e se dois produtores enviarem a mesma entrega ao mesmo tempo? Quem só decorou a demonstração trava; quem sabe por que tomou cada decisão responde com o código aberto. Como preparar dez minutos que mostrem funcionamento e raciocínio?

A apresentação prova duas coisas: que a API funciona e que o autor entende por que ela é assim. Um roteiro com problema, demonstração ao vivo, decisões e limites conhecidos, mais o ensaio das perguntas prováveis, separa quem entregou de quem sabe defender o que entregou.

  • 📄 Production Best Practices: Security — Express A lista oficial para conferir, antes da banca, o que a API já cobre.
  • 📄 OWASP Cheat Sheet Series O índice de referências para justificar cada defesa com fonte.
  • 📄 Software Testing Guide — Martin Fowler Vocabulário para explicar a estratégia de testes com precisão.
  • 📄 Web Services — Render Docs Como o serviço publicado funciona, para responder perguntas sobre o ambiente de produção.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: deixe abertas, em ordem, as abas da URL pública, do /docs, do repositório e do log do Render, e faça uma chamada antes para acordar a instância.
  2. Abertura: apresente o problema da cooperativa em 30 segundos, sem falar de tecnologia.
  3. Demonstração: mostre o fluxo principal ponta a ponta: login, criação de entrega com foto e aviso em tempo real no painel.
  4. Erro de Propósito na Demo: envie uma entrada inválida e mostre o 400 em Problem Details apontando o campo — prova de que o erro foi pensado.
  5. Decisões: explique três decisões de arquitetura, cada uma com a alternativa que foi descartada e o motivo.
  6. Qualidade: mostre os testes rodando e o resultado da auditoria de segurança.
  7. Limites Conhecidos: diga o que não foi feito, por que, e o que seria o próximo passo.
  8. Erro Provocado no Ensaio: peça a um colega três perguntas difíceis e anote as que você não conseguiu responder com o código aberto; estude essas partes.
  9. Tempo: ensaie com cronômetro até caber em dez minutos, com dois minutos de folga para perguntas.
  10. Validação e Testes: apresente, receba a rubrica preenchida e registre no README o retorno recebido e os próximos passos do projeto.
Concluiu todos os passos?
