📤 1. Recebendo Arquivos com multipart/form-data e Multer

🎯 Desafio

A imobiliária fictícia Lar Mineiro quer que o corretor anexe a foto do imóvel à tarefa de vistoria. O express.json() da API não entende arquivo, e o req.body chega vazio quando o formulário é enviado. Como fazer a API receber um arquivo binário junto com os campos de texto do formulário?

JSON transporta texto; arquivo viaja em multipart/form-data, um corpo dividido em partes separadas por um delimitador. O Multer, mantido pelo próprio time do Express, lê esse formato, entrega os campos de texto em req.body e o arquivo em req.file.

  • 📄 multer middleware — Express A página oficial do Multer no site do Express, com todas as opções.
  • 📄 Multer — README oficial single, array, fields, diskStorage, memoryStorage, limits e fileFilter.
  • 📄 Enviando dados de formulário — MDN Como o navegador monta o corpo multipart quando o formulário tem arquivo.
  • 📄 FormData — MDN O objeto que monta o mesmo corpo multipart a partir do JavaScript.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: instale npm install multer, crie a pasta uploads/ e acrescente uploads/ ao .gitignore.
  2. Formulário de Teste: crie public/teste-upload.html com <form method="post" enctype="multipart/form-data"> e <input type="file" name="foto">.
  3. Configuração Mínima: crie const upload = multer({ dest: 'uploads/' }) e a rota POST /tarefas/:id/anexos com upload.single('foto').
  4. Inspecionando o Arquivo: imprima req.file e observe originalname, mimetype, size e o nome aleatório gravado em disco.
  5. Erro Provocado: mude o name do input para imagem, envie e leia o erro Unexpected field; volte para foto.
  6. Controlando o Nome: troque dest por multer.diskStorage com filename gerado por crypto.randomUUID().
  7. Campos Junto do Arquivo: adicione ao formulário um campo legenda e leia em req.body.legenda.
  8. Sem Arquivo: responda 400 quando req.file vier undefined.
  9. Várias Fotos: crie uma segunda rota com upload.array('fotos', 5) e leia a lista em req.files.
  10. Validação e Testes: envie pelo formulário e pelo Insomnia com corpo Multipart Form, confira o arquivo na pasta e registre no README o formato do corpo enviado.

🛡️ 2. Validando Tamanho, Tipo e Conteúdo do Arquivo

🎯 Desafio

Na Lar Mineiro, alguém renomeou um script para foto.jpg e enviou pela rota de anexos; outro corretor mandou um vídeo de 900 MB que encheu o disco do servidor. A API confiou na extensão e não tinha limite de tamanho. Como aceitar só imagens de verdade e de tamanho razoável?

Extensão e mimetype vêm do cliente e podem mentir. A defesa em camadas combina limite de tamanho no próprio Multer, lista de tipos permitidos e checagem dos primeiros bytes do arquivo, a assinatura que identifica o formato real.

  • 📄 File Upload Cheat Sheet — OWASP A lista de controles para upload: tamanho, tipo, nome, armazenamento e permissão.
  • 📄 Unrestricted File Upload — OWASP O que um atacante consegue quando a API aceita qualquer arquivo.
  • 📄 Content-Type — MDN O cabeçalho que declara o tipo do conteúdo, e por que ele é só uma declaração.
  • 📄 API4:2023 Unrestricted Resource Consumption — OWASP Por que limite de tamanho e de quantidade é requisito de segurança, não detalhe.

  • ▶️ Como fazer UPLOAD de arquivos com NODE EXPRESS e MULTER | StartDev Codaro · 14:30 — Revisa o fluxo de upload com Express e Multer, ponto de partida para validar o arquivo recebido.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: troque o armazenamento para multer.memoryStorage(): o arquivo fica em req.file.buffer até ser aprovado e nada vai ao disco antes disso.
  2. Limite de Tamanho: configure limits: { fileSize: 2 * 1024 * 1024, files: 1 }.
  3. Erro Provocado: envie uma imagem de 5 MB e observe o MulterError com código LIMIT_FILE_SIZE sair como erro 500 genérico.
  4. Traduzindo o Erro: no middleware de erro da aula 26, converta MulterError em 413 quando for tamanho e 400 nos demais códigos.
  5. Primeiro Filtro: use fileFilter para aceitar só os tipos declarados image/jpeg, image/png e image/webp.
  6. Assinatura Real: compare os primeiros bytes do buffer com as assinaturas de JPEG (FF D8 FF), PNG (89 50 4E 47) e WebP (RIFF ... WEBP).
  7. Teste do Disfarce: renomeie um arquivo .txt para .jpg, envie e confirme a recusa com 415 mesmo tendo passado pelo fileFilter.
  8. Nome Definido pelo Servidor: gere o nome final com UUID e a extensão a partir do tipo detectado, nunca do originalname.
  9. Organização: isole a checagem em src/uploads/detectarImagem.js e o Multer configurado em src/uploads/upload.js.
  10. Validação e Testes: envie imagem válida, arquivo grande, arquivo disfarçado e campo com nome errado; registre no README o status que cada caso recebeu.

☁️ 3. Armazenamento no Supabase Storage

🎯 Desafio

O servidor gratuito da Lar Mineiro apaga a pasta uploads a cada novo deploy, e as fotos das vistorias somem. Além disso, fotos da casa de clientes não podem ficar num link público para sempre. Como guardar arquivos fora do servidor e entregá-los só a quem pode ver?

Servidor de API não é lugar de guardar arquivo: o disco da hospedagem gratuita é efêmero e não acompanha mais de uma instância. O Supabase Storage guarda os arquivos em buckets; o banco guarda só o caminho e os metadados, e a API entrega links assinados que expiram.

  • 📄 Storage — Supabase Docs Visão geral do serviço de arquivos do Supabase.
  • 📄 Storage Buckets — Supabase Docs A diferença entre bucket público e privado e quando usar cada um.
  • 📄 Upload a file — Supabase JavaScript A assinatura de upload com contentType e upsert.
  • 📄 Serving assets from Storage — Supabase Docs URL pública, URL assinada e download pelo cliente.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: no painel do Supabase, crie o bucket privado anexos.
  2. Tabela de Metadados: crie anexos com tarefa_id referenciando tarefas, caminho, tipo, tamanho e criado_em.
  3. Caminho Organizado: monte o caminho como tarefas/{id}/{uuid}.{extensao} para agrupar os arquivos por tarefa.
  4. Upload: chame supabase.storage.from('anexos').upload(caminho, req.file.buffer, { contentType }).
  5. Registrando: depois do upload, insira a linha em anexos com caminho, tipo e tamanho.
  6. Erro Provocado: envie duas vezes para o mesmo caminho fixo e leia o erro de recurso já existente; decida entre upsert: true ou nome novo.
  7. Compensação: se o insert no banco falhar, remova o arquivo com .remove([caminho]) para não deixar lixo no bucket.
  8. Link Assinado: crie GET /anexos/:id/link que chama createSignedUrl(caminho, 300) e devolve a URL.
  9. Expiração: abra o link, espere passar dos cinco minutos, abra de novo e observe a recusa.
  10. Validação e Testes: reinicie a API, confirme que a foto continua acessível por um link novo e registre no README por que o bucket é privado.
Concluiu todos os passos?
