🧪 1. Testes Unitários da Regra de Negócio

🎯 Desafio

A startup fictícia Rota Certa mexeu na regra que impede tarefa com título vazio e só descobriu três dias depois, quando um cliente reclamou. Ninguém tinha como saber, antes do deploy, que a regra tinha deixado de valer. Como fazer a própria máquina avisar em segundos que uma regra quebrou?

Teste unitário exercita uma peça isolada — o caso de uso da aula 23 — sem HTTP e sem banco. Ele roda em milissegundos, aponta a linha que quebrou e vira documentação executável da regra.

  • 📄 Primeiros passos — Jest Instalação, o primeiro teste e o comando que roda a suíte inteira.
  • 📄 Funções Mock — Jest Como criar dublês com jest.fn() e verificar quantas vezes e com quais argumentos foram chamados.
  • 📄 Test runner nativo — Node.js A alternativa embutida no Node, útil para comparar o que um framework de teste acrescenta.
  • 📄 The Practical Test Pyramid — Martin Fowler Por que a base da pirâmide tem muitos testes unitários rápidos e poucos testes lentos no topo.
🎥 Vídeos de apoio
  • ▶️ Aprenda testar seu backend Node JS com Jest Fernanda Kipper · 37:00 — Ensina a escrever testes com Jest para o backend Node.js, isolando a regra de negócio.
  • ▶️ Aulão de Unit Tests em Node.js com Jest LuizTools · 41:18 — Aula longa sobre testes unitários em Node.js com Jest, do setup às asserções.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: no projeto da aula 23, rode npm install --save-dev jest e adicione "test": "jest" em scripts no package.json.
  2. Primeiro Arquivo de Teste: crie tests/unit/CriarTarefa.test.js — o Jest encontra sozinho os arquivos terminados em .test.js.
  3. Estrutura Preparar-Agir-Verificar: escreva um describe('CriarTarefa') e, dentro dele, um test dividido em três blocos: preparar, agir e verificar.
  4. Dublê do Repositório: em vez do repositório real, crie um objeto com salvar: jest.fn(async (t) => ({ ...t, id: 1 })) e passe-o ao construtor do caso de uso.
  5. Caso Feliz: execute o caso de uso com um título válido e compare o retorno com expect(resultado).toEqual(...).
  6. Verificando a Interação: confirme com toHaveBeenCalledTimes(1) que o repositório foi chamado exatamente uma vez.
  7. Erro Provocado: remova o await antes de caso.executar, rode npm test e leia a falha: o teste comparou uma Promise, não a tarefa. Devolva o await.
  8. Caso de Erro: teste que título só com espaços rejeita com await expect(...).rejects.toThrow() e que salvar não foi chamado.
  9. Medindo a Cobertura: rode npx jest --coverage e localize as linhas de src/core que nenhum teste percorreu.
  10. Validação e Testes: quebre de propósito a regra do título na entidade, confirme que o teste fica vermelho, desfaça a mudança e registre no README o comando de teste e a cobertura obtida.
Concluiu todos os passos?

🔌 2. Testes de Integração das Rotas HTTP

🎯 Desafio

Na clínica fictícia Vida Plena, os testes do caso de uso passavam, mas a rota POST /tarefas respondia erro porque alguém apagou o express.json() numa limpeza de código. O teste unitário não viu, porque não passa pelo HTTP. Como testar a API do jeito que o cliente chama, sem subir o servidor na mão?

O teste de integração dispara requisições reais contra o app Express e confere status, cabeçalhos e corpo. Para isso o app precisa ser criado separado do listen: é essa separação que permite testar sem ocupar porta e com um repositório novo a cada teste.

  • 📄 Supertest — repositório oficial A biblioteca que envia requisições ao app Express direto na memória, com asserções encadeadas.
  • 📄 Setup and Teardown — Jest beforeEach e afterAll: como recriar o estado antes de cada teste para um não depender do outro.
  • 📄 Códigos de status HTTP — MDN A referência para decidir qual status cada teste deve esperar.
  • 📄 Software Testing Guide — Martin Fowler Índice de artigos sobre tipos de teste, dublês e onde cada um se encaixa.
🎥 Vídeos de apoio
  • ▶️ Teste de integração no Node com Jest e SuperTest Hero Code · 21:32 — Mostra como fazer testes de integração de rotas Express com Jest e SuperTest.
  • ▶️ Testes de API em Javascript com Supertest + Jest (passo a passo) Agilizei · 51:14 — Passo a passo de testes de API com Supertest e Jest conferindo status e corpo da resposta.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: instale npm install --save-dev supertest no mesmo projeto da prática anterior.
  2. Separando App e Servidor: transforme src/app.js numa função criarApp(repositorio) que devolve o app sem chamar listen; o listen vai para server.js.
  3. Primeiro Teste de Rota: em tests/integration/tarefas.test.js, importe request do supertest e chame await request(app).get('/tarefas').
  4. Estado Isolado: use beforeEach para criar um repositório em memória novo e um app novo antes de cada teste.
  5. Testando a Criação: envie .post('/tarefas').send({ titulo: 'Ligar para fornecedor' }) e verifique status 201 e o id no corpo.
  6. Erro Provocado: apague temporariamente app.use(express.json()), rode os testes e observe o status que volta no lugar do 201 e a mensagem de TypeError. Devolva a linha.
  7. Entrada Inválida: teste que POST sem título devolve 400 com a mensagem da entidade.
  8. Recurso Inexistente: teste que GET /tarefas/9999 devolve 404.
  9. Cabeçalhos: verifique com expect(resposta.headers['content-type']).toMatch(/json/) que a API responde JSON.
  10. Validação e Testes: rode npm test e confirme unitários e integração passando juntos; registre no README qual erro cada tipo de teste consegue pegar.
Concluiu todos os passos?

📘 3. Documentação da API com OpenAPI e Swagger UI

🎯 Desafio

O time de frontend da loja fictícia Casa Aurora pergunta toda semana, no chat, quais campos a rota de tarefas aceita e que erro ela devolve. A resposta muda conforme quem responde. Como publicar um contrato único que o time consulta e testa sem depender de ninguém?

OpenAPI é um formato padrão, em YAML ou JSON, que descreve rotas, parâmetros, corpos e respostas de uma API HTTP. A partir dele, o Swagger UI gera uma página onde se lê e se testa cada rota, e a documentação passa a ser um arquivo versionado junto do código.

  • 📄 Introdução ao OpenAPI — OpenAPI Initiative O que o formato resolve e como um documento OpenAPI é organizado.
  • 📄 OpenAPI Specification 3.1.1 A especificação oficial: consulte quando precisar do nome exato de um campo.
  • 📄 swagger-ui-express — repositório oficial O middleware que serve o Swagger UI a partir do seu documento OpenAPI.
  • 📄 Swagger UI — Instalação As formas de distribuir o Swagger UI e o que a página faz com o documento.
🎥 Vídeos de apoio
  • ▶️ Criando API auto-documentável com Node.js e Swagger Rocketseat · 17:47 — Mostra como documentar uma API Node.js com Swagger a partir da especificação OpenAPI.
  • ▶️ Swagger (suas APIs documentadas sem esforço) // Dicionário do Programador Código Fonte TV · 7:54 — Explica o que é o Swagger e como ele gera documentação navegável de uma API.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: instale npm install swagger-ui-express yaml e crie o arquivo docs/openapi.yaml.
  2. Cabeçalho do Contrato: declare openapi: 3.1.0, o bloco info com título e versão, e servers apontando para http://localhost:3000.
  3. Esquema Reutilizável: em components.schemas, descreva Tarefa com id, titulo e feita, e um esquema Erro.
  4. Primeira Rota: documente GET /tarefas com resposta 200 apontando para o esquema via $ref.
  5. Rota com Corpo: documente POST /tarefas com requestBody obrigatório e titulo do tipo string.
  6. Respostas de Erro: acrescente 400 e 404 usando o esquema Erro: o contrato também diz o que dá errado.
  7. Servindo a Página: no server.js, leia o YAML com YAML.parse(fs.readFileSync(...)) e registre app.use('/docs', swaggerUi.serve, swaggerUi.setup(documento)).
  8. Erro Provocado: desalinhe a indentação de uma linha do YAML, reinicie o servidor e siga a mensagem do parser até achar a linha e a coluna do problema.
  9. Testando pela Página: abra http://localhost:3000/docs, use Try it out no POST e compare o resultado com o teste de integração.
  10. Validação e Testes: confira que toda rota do app aparece no contrato com os mesmos status que os testes verificam e coloque o link /docs no README.
Concluiu todos os passos?
