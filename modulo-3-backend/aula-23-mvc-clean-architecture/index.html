🗂️ 1. MVC: a Separação que Todo Framework Assume

Model, View e Controller nasceram em interface gráfica nos anos 70 e viraram o vocabulário padrão do backend. Entender o original evita o erro mais comum: chamar de MVC qualquer pasta com três nomes.

  • 📄 MVC — Glossário da MDN A definição curta e correta das três camadas, sem o folclore que se acumulou em volta.
  • 📄 Catálogo de Padrões — Martin Fowler O catálogo do Patterns of Enterprise Application Architecture, com os padrões que sustentam o MVC.
  • 📄 Presentation Domain Data Layering Por que a separação em três camadas aparece em praticamente todo sistema que cresceu.
  • 📄 Roteamento no Express Onde o roteador se encaixa: ele é a porta, não o controlador.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: abra o controlador da aula 22 e conte quantas responsabilidades diferentes há nele.
  2. Mapeando as Misturas: marque com comentário cada trecho que é validação, regra de negócio ou acesso a dado.
  3. Estrutura de Pastas: confirme que existem controllers, services e crie repositories.
  4. Extraindo o Acesso a Dado: mova toda manipulação do array para tarefas.repository.js.
  5. Definindo o Contrato: o repositório expõe buscarTodos, buscarPorId, salvar e remover.
  6. Movendo a Regra: deixe no serviço as decisões — o que é válido, o que pode, o que acontece depois.
  7. Emagrecendo o Controlador: ele deve apenas ler a requisição, chamar o serviço e montar a resposta.
  8. Testando o Isolamento: escreva um script que chama o serviço direto, sem HTTP, e imprime o resultado.
  9. Medindo o Resultado: compare as linhas do controlador antes e depois da refatoração.
  10. Validação e Testes: rode todas as rotas e confirme que o comportamento externo continua idêntico.

🎯 2. Clean Architecture: a Regra de Dependência

A ideia central cabe numa frase: as dependências apontam para dentro. O caso de uso não sabe que existe Express, e a regra de negócio não sabe que existe Postgres.

  • 📄 The Clean Architecture — artigo original O texto de Robert C. Martin que nomeou o padrão, com o diagrama dos círculos concêntricos.
  • 📄 Domain-Driven Design — Martin Fowler A base conceitual de modelar o domínio antes da tecnologia.
  • 📄 Inversão de Controle e Injeção de Dependência O mecanismo concreto que permite inverter a seta da dependência.
  • 📄 Twelve-Factor — Serviços de Apoio Banco, cache e fila como recursos anexados, trocáveis sem mudar o código.

🎥 Curadoria de vídeo pendente. Este bloco recebe os vídeos de apoio selecionados pelo instrutor para o tema acima.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie a pasta src/core ao lado de src/infra.
  2. Criando a Entidade: em core/entities/Tarefa.js, escreva a classe com as regras que valem sempre.
  3. Regra na Entidade: impeça no construtor a criação de tarefa com título vazio.
  4. Definindo o Contrato: documente em core/ports/TarefaRepository.js os métodos que o caso de uso espera.
  5. Escrevendo o Caso de Uso: em core/usecases/CriarTarefa.js, receba o repositório por parâmetro do construtor.
  6. Proibindo o Import: confirme que nenhum arquivo de core importa Express ou qualquer biblioteca de banco.
  7. Adaptador em Memória: implemente o contrato em infra/repositories/TarefaMemoriaRepository.js.
  8. Ligando na Borda: no controlador, instancie o caso de uso passando o adaptador concreto.
  9. Trocando a Implementação: escreva um segundo adaptador que grava em arquivo JSON e troque só a linha de instanciação.
  10. Validação e Testes: rode a API com os dois adaptadores e confirme que nenhuma linha de core precisou mudar.

⚖️ 3. Quando Não Vale a Pena: o Custo da Camada

Arquitetura é escolha com preço. Cinco camadas numa API de três rotas é tão ruim quanto nenhuma camada numa API de cinquenta. O bloco fecha com o critério de quando parar.

  • 📄 YAGNI — You Aren't Gonna Need It O argumento contra construir a abstração antes de precisar dela.
  • 📄 Design Stamina Hypothesis O ponto em que investir em desenho passa a render mais do que custa.
  • 📄 Dívida Técnica — Martin Fowler Como pensar o atalho de hoje como empréstimo com juros, e não como erro.
  • 📄 Google — O padrão de um code review O critério que o Google usa: melhora a saúde do sistema, mesmo sem ser perfeito.

  9. Escrevendo o Custo: para cada proposta, escreva o que piora — toda escolha tem contrapartida.
  10. Validação e Testes: apresente as duas propostas ao instrutor e defenda cada uma com o critério que usou.
