🌐 1. fetch, JSON e Renderização de Dados Externos

🎯 Desafio

O blog fictício Café com Código quer mostrar na página inicial os posts mais recentes, mas hoje alguém copia os títulos à mão no HTML toda semana. Os posts já existem numa API que devolve JSON. Como buscar esses dados com JavaScript e transformar a resposta em cards na tela, carregando mais quando o leitor pedir?

fetch é a função do navegador para fazer requisições HTTP. Ela devolve uma Promise com a resposta, e o corpo em JSON precisa ser lido com response.json(), que também é assíncrono. Com os dados em mãos, a tela é montada com os mesmos métodos de array da Aula 4.

  • 📄 Using the Fetch API — MDN O guia completo: fazer a requisição, ler o corpo e configurar método e cabeçalhos.
  • 📄 Response: json() — MDN Por que ler o corpo é uma segunda etapa assíncrona e o que acontece se o corpo não for JSON.
  • 📄 JSONPlaceholder — Guide Os recursos disponíveis na API de testes e exemplos de filtro e paginação pela URL.
  • 📄 Making network requests — MDN Learn O fluxo requisição → resposta → atualização da página com exemplos guiados.

🚦 2. Estados de Carregamento, Erro e Resposta Vazia

🎯 Desafio

Na loja fictícia Vitrine Norte, quando a API demora a tela fica em branco; quando ela devolve 404, a página mostra 'undefined' no lugar do nome; e quando não há resultados, aparece só um espaço vazio. Os clientes acham que o site quebrou. Como a interface pode avisar o que está acontecendo em cada situação: carregando, deu certo, veio vazio ou falhou?

Uma requisição tem pelo menos quatro desfechos que a interface precisa mostrar. O fetch só rejeita em falha de rede; respostas 404 ou 500 chegam como sucesso, e quem confere é o código, com response.ok e response.status. Um tempo limite evita a espera infinita.

  • 📄 Response: ok — MDN A propriedade que diz se o status está entre 200 e 299, e por que o fetch não rejeita em 404.
  • 📄 Response: status — MDN Como ler o código numérico da resposta para escolher a mensagem certa.
  • 📄 HTTP response status codes — MDN O significado de cada faixa de status: 2xx, 4xx e 5xx.
  • 📄 AbortSignal.timeout() — MDN Como cancelar uma requisição que passou do tempo limite com uma linha.

📮 3. Parâmetros na URL, Envio de Dados e Formulário de CEP

🎯 Desafio

A transportadora fictícia Leva Já perde entregas porque os clientes digitam o endereço errado no cadastro. A ideia é pedir só o CEP, preencher rua, bairro e cidade sozinho e depois enviar o cadastro para o servidor. Como montar a URL da consulta a partir do que o usuário digitou, validar o formato antes de chamar a API e tratar o CEP que não existe?

O dado que o usuário digita vira parte da URL de uma requisição GET, por isso precisa ser limpo e validado antes. Para enviar dados, o mesmo fetch recebe method, headers e body. APIs como o ViaCEP também têm regras próprias, como responder com erro dentro de um JSON de status 200.

  • 📄 ViaCEP — documentação oficial O formato da URL de consulta, a resposta em JSON e o campo de erro para CEP inexistente.
  • 📄 Window: fetch() — MDN As opções do fetch: method, headers e body para enviar dados ao servidor.
  • 📄 encodeURIComponent() — MDN Por que texto digitado pelo usuário deve ser codificado antes de entrar numa URL.
  • 📄 Atributo pattern — MDN Validar o formato do campo no próprio HTML antes de qualquer requisição.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie a pasta aula-6-cep com os três arquivos e um formulário com CEP, rua, bairro, cidade, UF e número.
  2. Validação no HTML: no campo CEP, use inputmode="numeric" e pattern="\d{5}-?\d{3}" com uma mensagem de ajuda.
  3. Limpando a Entrada: crie limparCep(valor) que remove tudo que não for dígito com replace(/\D/g, '').
  4. Montando a URL: monte https://viacep.com.br/ws/${cep}/json/ com encodeURIComponent e só chame a API se houver 8 dígitos.
  5. Consulta no blur: busque o endereço quando o campo CEP perder o foco (evento blur) e mostre 'Buscando...'.
  6. Erro Provocado: consulte o CEP 99999-999 e observe que a resposta tem status 200 com { "erro": true }.
  7. Tratando a Regra da API: verifique dados.erro e mostre 'CEP não encontrado' limpando os campos.
  8. Preenchendo o Formulário: copie logradouro, bairro, localidade e uf para os campos e leve o foco para Número.
  9. Enviando com POST: no submit, envie o cadastro para https://jsonplaceholder.typicode.com/users com method: 'POST', cabeçalho JSON e JSON.stringify.
  10. Validação e Testes: teste um CEP válido, um inexistente e um incompleto, confira o status 201 do POST na aba Rede e registre no README.
