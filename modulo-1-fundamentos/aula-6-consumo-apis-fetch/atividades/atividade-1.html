Mural de Posts — fetch e JSONPlaceholder

Aula 6 · Módulo 1: Fundamentos · ByteClass

O que esta atividade entrega

Um mural que busca posts na API pública JSONPlaceholder, desenha cada post como card e carrega o próximo lote quando o leitor clica em 'Carregar mais'.

script.js

// Início: mural de posts com fetch e paginação
const URL_POSTS = 'https://jsonplaceholder.typicode.com/posts';
const POR_PAGINA = 6;

const mural = document.querySelector('#mural');
const statusTexto = document.querySelector('#status');
const btnMais = document.querySelector('#btnMais');
let pagina = 0;

// monta a URL do lote atual usando os parâmetros da API
const montarUrl = (numeroPagina) => `${URL_POSTS}?_start=${numeroPagina * POR_PAGINA}&_limit=${POR_PAGINA}`;

// transforma um post no HTML de um card
const cardDoPost = (post) => `<article class="post"><small>#${post.id} · autor ${post.userId}</small><h2>${post.title}</h2><p>${post.body.slice(0, 80)}...</p></article>`;

// busca um lote de posts e acrescenta ao mural
async function carregarPosts() {
  btnMais.disabled = true;
  statusTexto.textContent = 'Carregando...';
  try {
    const resposta = await fetch(montarUrl(pagina));
    const posts = await resposta.json();
    mural.insertAdjacentHTML('beforeend', posts.map(cardDoPost).join(''));
    pagina += 1;
    statusTexto.textContent = `${mural.children.length} posts carregados.`;
    if (posts.length < POR_PAGINA) {
      btnMais.textContent = 'Fim dos posts';
      return;
    }
  } catch (erro) {
    statusTexto.textContent = 'Não foi possível carregar os posts. Tente de novo.';
  }
  btnMais.disabled = false;
}

btnMais.addEventListener('click', carregarPosts);
carregarPosts();
// Fim de script.js

Como rodar

  1. Crie uma pasta com os arquivos index.html, style.css e script.js.
  2. Cole cada bloco de código acima no arquivo com o mesmo nome.
  3. Abra o index.html no navegador (duplo clique ou Live Server no VS Code).
  4. Clique em 'Carregar mais' algumas vezes e acompanhe as requisições na aba Rede do DevTools.

O que observar

  • São duas esperas: uma pelo fetch (cabeçalhos da resposta) e outra pelo json() (corpo).
  • A paginação é feita pela URL: _start e _limit mudam, o código de renderização não.
  • Aqui qualquer falha vira a mesma mensagem genérica; separar 404, resposta vazia e tempo limite é o assunto da atividade 2.
