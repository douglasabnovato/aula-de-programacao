⏳ 1. Código Assíncrono, Callbacks e o Event Loop

🎯 Desafio

A central fictícia de entregas Rota Certa consulta o status de cada pacote num sistema que demora alguns segundos para responder. Na primeira versão, o código fica num laço esperando a resposta e, enquanto isso, nenhum botão da página responde ao clique. Por que a tela congela e como pedir ao navegador para avisar quando o dado chegar, em vez de ficar parado esperando?

O JavaScript do navegador roda numa única linha de execução: enquanto um trecho está rodando, nada mais acontece na página. Tarefas demoradas são entregues ao navegador com uma função de retorno (callback), e o event loop devolve essa função para a fila quando o resultado fica pronto.

  • 📄 Callback function — Glossário MDN O que é passar uma função para outra chamar depois, com exemplo curto.
  • 📄 setTimeout() — MDN Como agendar uma função e por que o atraso é um mínimo, não uma garantia.
  • 📄 JavaScript execution model — MDN Pilha de chamadas, fila de tarefas e o laço de eventos explicados pela documentação.

🤝 2. Promises: then, catch e Promise.all

🎯 Desafio

A loja fictícia Estação Games monta a tela de um pedido juntando três respostas: dados do cliente, itens comprados e prazo de frete. Com callbacks, o código virou uma escada de funções dentro de funções e, quando o frete falha, ninguém vê o erro. Como encadear as três etapas, tratar a falha num lugar só e ainda buscar tudo ao mesmo tempo?

Uma Promise é um objeto que representa um resultado que ainda vai chegar: ela começa pendente e termina cumprida ou rejeitada. Com then, catch e finally o fluxo fica numa cadeia plana, e Promise.all espera várias operações em paralelo.

✍️ 3. async/await e Tratamento de Falhas

🎯 Desafio

O app fictício Agenda Vet confirma consultas em duas etapas: verifica se o horário está livre e depois faz a reserva. O código com then ficou difícil de ler e, quando a reserva falha, o botão fica travado em 'Confirmando...' para sempre. Como escrever o mesmo fluxo de cima para baixo, como código comum, garantindo que o botão volte ao normal com ou sem erro?

async e await são outra forma de escrever código com Promises: a função pausa no await até o resultado chegar, sem travar a página. Erros de Promises rejeitadas passam a ser capturados com try/catch, e finally garante a limpeza da interface.

  • 📄 await — MDN Como a pausa funciona e o que acontece quando a Promise esperada é rejeitada.
  • 📄 Promise.allSettled() — MDN Esperar várias operações e receber o resultado de cada uma, inclusive das que falharam.
  • 📄 SyntaxError: await is only valid in async functions — MDN O erro mais comum de quem começa com await, explicado com a correção.
