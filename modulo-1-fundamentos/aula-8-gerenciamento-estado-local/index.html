🗂️ 1. Estado Único e Renderização a partir dos Dados

🎯 Desafio

O quadro de tarefas fictício da equipe Mutirão Digital guarda informação em dois lugares: num array do JavaScript e nas classes CSS do HTML. Quando alguém marca uma tarefa como feita, a lista muda, mas o contador no topo e o filtro 'pendentes' continuam mostrando o valor antigo, porque cada parte da tela é alterada por um trecho de código diferente. Como fazer a tela inteira sempre refletir uma única fonte de dados?

Estado é o conjunto de dados que decide o que aparece na tela. Quando ele fica num único objeto e toda mudança passa por uma função que atualiza o estado e redesenha a interface, a tela deixa de ter partes desencontradas. É a mesma ideia que o React usa, aqui escrita à mão.

  • 📄 Reacting to Input with State — react.dev Pensar a interface como estados descritos por dados, e não como uma sequência de alterações no DOM.
  • 📄 Choosing the State Structure — react.dev Evitar estado duplicado ou derivado: guardar o mínimo e calcular o resto.
  • 📄 Object.freeze() — MDN Congelar o estado para provocar erro quando alguém tenta alterá-lo por fora.
  • 📄 Element: classList — MDN Aplicar classes a partir do estado, em vez de usar a classe como fonte de verdade.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie a pasta aula-8-quadro com os três arquivos, um contador no topo, botões de filtro e uma lista vazia.
  2. Desenhando o Estado: escreva no README o objeto estado = { tarefas, filtro } e o que a tela mostra a partir dele.
  3. Estado Inicial: declare let estado com quatro tarefas { id, texto, feita } e filtro: 'todas'.
  4. Dado Derivado: calcule o número de pendentes dentro do render com filter, em vez de guardar um contador separado.
  5. Função render: crie render() que redesenha contador, botões de filtro e lista a partir de estado.
  6. Função de Atualização: crie setEstado(parcial) que faz estado = { ...estado, ...parcial } e chama render().
  7. Erro Provocado: altere estado.filtro direto no console e observe que a tela não muda até o próximo setEstado.

  9. Marcando Tarefas: no clique de uma tarefa, gere um array novo com map trocando feita e passe para setEstado.
  10. Validação e Testes: marque tarefas com cada filtro ativo, confira que contador e lista sempre concordam e registre no README.

🎯 2. Ações, Delegação de Eventos e data-attributes

🎯 Desafio

A lista de compras do app fictício Feira da Semana tem dezenas de itens, e cada botão de aumentar, diminuir e remover recebe um addEventListener novo a cada renderização. A página fica lenta e, às vezes, um clique conta duas vezes. Como ouvir todos esses cliques com um único ouvinte e decidir o que fazer pelo tipo de ação?

Eventos sobem do elemento clicado até os ancestrais (bubbling). Com um único ouvinte no container, event.target e closest descobrem qual botão foi clicado, e atributos data-* dizem qual ação e qual item. As mudanças de estado ficam concentradas numa função que recebe a ação e devolve o estado novo.

  • 📄 Event bubbling — MDN Learn Como o evento sobe pela árvore e por que isso permite a delegação.
  • 📄 Event: target — MDN Descobrir exatamente qual elemento recebeu o clique.
  • 📄 HTMLElement: dataset — MDN Ler atributos data-* no JavaScript e a conversão de nomes com hífen.
  • 📄 Extracting State Logic into a Reducer — react.dev A ideia de concentrar as mudanças de estado numa função que recebe ações.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie a pasta aula-8-feira com os três arquivos, um formulário de novo item e uma <ul> vazia.
  2. Estado da Lista: declare estado = { itens: [...] } com itens { id, nome, qtd }.
  3. Botões com Dados: no render, gere botões com data-acao="aumentar", "diminuir" ou "remover" e data-id do item.
  4. Erro Provocado: adicione um ouvinte em cada botão dentro do render, sem remover os antigos, e conte quantas vezes o clique roda.
  5. Um Único Ouvinte: apague esses ouvintes e registre um só click na <ul>, fora do render.
  6. Descobrindo o Botão: use evento.target.closest('button[data-acao]') e ignore cliques fora de botões.
  7. Lendo os Dados: leia botao.dataset.acao e Number(botao.dataset.id).
  8. Função de Ações: crie atualizar(estado, acao) com switch (acao.tipo) devolvendo sempre um estado novo.
  9. Despachando: crie despachar(acao) que calcula o estado novo, registra a ação num log e chama render().
  10. Validação e Testes: clique rápido em vários botões, confira o log de ações e registre no README por que um ouvinte basta.

💾 3. Persistência com localStorage

🎯 Desafio

O app fictício Hábito Diário perde todos os check-ins da semana quando o usuário atualiza a página, e as pessoas desistem de usar no segundo dia. O projeto ainda não tem backend. Como guardar o estado no próprio navegador, restaurá-lo ao abrir a página e não quebrar a tela quando o dado salvo estiver corrompido?

localStorage guarda pares de texto no navegador, por site, e sobrevive ao recarregamento. Como só aceita strings, o estado vai com JSON.stringify e volta com JSON.parse. Uma chave com versão e uma leitura protegida por try/catch evitam que um dado velho ou inválido derrube a aplicação.

  • 📄 Using the Web Storage API — MDN Guia com setItem, getItem, removeItem e o cuidado com navegadores que bloqueiam o armazenamento.
  • 📄 Window: localStorage — MDN Onde os dados ficam, quanto tempo duram e por que tudo vira string.
  • 📄 JSON.stringify() — MDN Transformar o objeto de estado em texto para salvar.
  • 📄 JSON.parse() — MDN Voltar o texto para objeto e o SyntaxError quando o texto está corrompido.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie a pasta aula-8-habitos com os três arquivos e uma grade vazia para hábitos x dias da semana.
  2. Estado e Chave: declare CHAVE = 'habito-diario:v1' e um estadoInicial com três hábitos e sete dias marcados como false.
  3. Render da Grade: crie render() que desenha um checkbox por dia, com data-habito e data-dia.
  4. Erro Provocado: salve o objeto direto com localStorage.setItem(CHAVE, estado) e leia no DevTools o texto [object Object].
  5. Salvando como JSON: crie salvar() com JSON.stringify(estado) e chame-a em toda mudança de estado.
  6. Carregando na Abertura: crie carregar() que lê a chave e usa JSON.parse, devolvendo estadoInicial se não houver nada.
  7. Protegendo a Leitura: envolva carregar() em try/catch: se o JSON estiver inválido, avise e volte ao estado inicial.
  8. Testando Corrupção: grave '{quebrado' na chave pelo console, recarregue e confirme que a página abre com o aviso.
  9. Limpando: adicione um botão que chama localStorage.removeItem(CHAVE) e restaura o estado inicial.
  10. Validação e Testes: marque dias, recarregue a página, confira a aba Application do DevTools e registre no README o que fica salvo.
