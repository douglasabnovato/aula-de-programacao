Por que limitar o trabalho em andamento acelera

Cinco itens começados e nenhum terminado entregam zero valor. Dois itens começados e três terminados entregam três. O limite de WIP não é burocracia: é o que força terminar antes de começar.

Um quadro honesto

A FAZER      │ FAZENDO (3) │ REVISÃO (2) │ PRONTO
─────────────┼─────────────┼─────────────┼────────
 item 5      │  item 1     │  item 8     │ item 2
 item 6      │  item 4     │             │ item 3
 item 7      │             │             │
             │             │             │
             │  ← limite   │  ← limite   │
             │    3        │    2        │

O número na coluna é o limite. Para puxar um item novo para "Fazendo", um dos que estão lá precisa sair.

As três métricas e o que cada uma responde

Lead time Do pedido à entrega. É o que o cliente sente.
Cycle time Do início do trabalho à entrega. É o que a equipe controla.
Throughput Quantos itens saem por semana. É o que permite prever.

A diferença entre lead time e cycle time é o tempo de fila. Quando ela é grande, o problema não é a equipe ser lenta — é ter coisa demais esperando.

Scrum ou Kanban: o critério

Scrum serve quando o trabalho é planejável em ciclos, dá para proteger a equipe de interrupção, e existe alguém no papel de priorizar.
Kanban serve quando a demanda chega o tempo todo e com urgências reais — suporte, sustentação, time de plataforma.

Forçar Scrum num time de sustentação produz o pior dos dois mundos: a sprint é furada toda semana por urgência, e a equipe conclui que "ágil não funciona aqui". Não era ágil que não funcionava — era o framework errado para o tipo de trabalho.
