# Matriz de competências — Carla
Papel desejado (18 meses): desenvolvedora fullstack plena
Escala: 1 conheço o nome | 2 faço com ajuda | 3 faço sozinha | 4 ensino

| Competência                         | Esperado | Atual | Evidência                          | Lacuna |
|-------------------------------------|----------|-------|------------------------------------|--------|
| Componentes React                   | 3        | 3     | 4 telas entregues no app da Aurora | 0      |
| Testes automatizados                | 3        | 1     | nenhum teste escrito em produção   | 2      |
| API REST com Node                   | 3        | 1     | só tutorial                        | 2      |
| Banco de dados relacional (SQL)     | 3        | 2     | consultas com ajuda do sênior      | 1      |
| Deploy e variáveis de ambiente      | 2        | 2     | publicou projeto pessoal           | 0      |
| Escrever história de usuário        | 2        | 2     | escreveu 3 com revisão do PO       | 0      |
| Revisar código de colegas           | 3        | 1     | nunca revisou PR                   | 2      |
| Explicar decisão técnica ao time    | 3        | 2     | 1 apresentação na daily            | 1      |

## Três lacunas escolhidas
1. API REST com Node — sem ela o papel fullstack não existe.
2. Testes automatizados — exigido em todo PR do time.
3. Revisar código — é como um pleno multiplica o time.

## Segunda opinião (gestor)
- Testes: concordou com 1.
- Explicar decisão: deu 3 ("você explicou bem a troca de biblioteca").

Como usar

  1. Escolha o papel antes de listar competências.
  2. Dê notas só com evidência; sem fato, a nota desce.
  3. Peça uma segunda opinião em pelo menos três linhas.

O que observar

  • A lacuna maior nem sempre é a mais importante — a escolha é justificada pelo papel.
  • O gestor deu nota maior que a da Carla numa competência: autoavaliação erra para os dois lados.
  • A coluna de evidência vem do diário técnico da aula 48.
