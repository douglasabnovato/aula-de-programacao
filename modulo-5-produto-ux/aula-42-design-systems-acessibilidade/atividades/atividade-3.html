Componente de Botão — Contrato e Seis Estados

Aula 42 · Módulo 5: Produto, UX e Agilidade · ByteClass

O contrato, escrito antes do CSS

Botão
  variações: primaria | secundaria
  tamanhos:  md | sm
  estados:   padrão, hover, foco, ativo, desabilitado, carregando
  fora do escopo: ícone à direita, botão com menu (virá depois)

Escrever o que fica fora evita que o componente vire um canivete suíço.

CSS usando só tokens

.botao {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  gap: var(--esp-2);
  padding: var(--esp-2) var(--esp-4);
  border-radius: 10px;
  border: 1px solid transparent;
  font: 700 var(--txt-sm)/1 inherit;
  cursor: pointer;
  transition: background-color .18s ease, border-color .18s ease;
}

.botao--primaria {
  background-color: var(--cor-acao);
  color: var(--cor-fundo);
}

.botao--primaria:hover  { background-color: var(--cor-acao-forte); }

.botao--secundaria {
  background-color: transparent;
  border-color: var(--cor-borda);
  color: var(--cor-texto);
}

.botao--secundaria:hover { border-color: var(--cor-acao); color: var(--cor-acao); }

.botao:focus-visible {
  outline: 3px solid var(--cor-acao);
  outline-offset: 3px;
}

/* Atributo, não classe: assim o estado real do DOM e o visual não divergem. */
.botao[disabled] {
  opacity: .5;
  cursor: not-allowed;
}

.botao[aria-busy="true"] { pointer-events: none; }

Por que [disabled] e não .desabilitado

Com uma classe, é possível o botão parecer desabilitado e continuar clicável — ou o contrário. Estilizando pelo atributo, o visual é consequência do estado real: não tem como divergir.
