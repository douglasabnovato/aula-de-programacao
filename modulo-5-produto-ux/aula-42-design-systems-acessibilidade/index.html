🎨 1. Tokens: o Design Vira Variável

Um design system começa muito antes de uma biblioteca de componentes. Começa quando a cor deixa de ser escrita à mão em 40 lugares e passa a ter nome.

  • 📄 Design Tokens — Material Design 3 A definição e a hierarquia de tokens, com exemplos de nomenclatura.
  • 📄 Propriedades Customizadas CSS — MDN A mecânica das variáveis CSS: escopo, herança e fallback.
  • 📄 prefers-color-scheme — MDN Como respeitar a preferência de tema do sistema operacional do usuário.
  • 📄 web.dev — Learn Responsive Design Curso gratuito do Google sobre design responsivo, com foco em CSS moderno.

🎥 Curadoria de vídeo pendente. Este bloco recebe os vídeos de apoio selecionados pelo instrutor para o tema acima.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: escolha um projeto do catálogo com CSS próprio e abra o arquivo de estilo.
  2. Medindo o Ponto de Partida: conte quantas cores literais existem no arquivo e anote o número.
  3. Listando as Cores: extraia todas para uma lista e agrupe as que são quase iguais.
  4. Criando Tokens Primitivos: nomeie por valor — --verde-500, --cinza-900.
  5. Criando Tokens Semânticos: nomeie por função — --cor-acao, --cor-superficie.
  6. Apontando um para o Outro: faça o semântico apontar para o primitivo, nunca o contrário.
  7. Substituindo no CSS: troque todas as cores literais pelas variáveis semânticas.
  8. Medindo de Novo: conte as cores literais restantes — devem estar todas dentro do :root.
  9. Tema Alternativo: redefina só os tokens semânticos num bloco prefers-color-scheme.
  10. Validação e Testes: alterne o tema do sistema operacional e confirme que a página inteira acompanha.
Concluiu todos os passos?

♿ 2. Acessibilidade: o Mínimo que Não é Opcional

Acessibilidade tem fama de tema difícil e caro. A maior parte do ganho vem de quatro coisas simples que já deveriam estar no código: HTML semântico, foco visível, rótulo e contraste.

  • 📄 WCAG 2.1 — Referência Rápida Todos os critérios de sucesso filtráveis por nível, com técnica de implementação.
  • 📄 ARIA Authoring Practices — Padrões Como construir modal, acordeão, abas e menu de forma acessível, com exemplo de código.
  • 📄 web.dev — Learn Accessibility Curso gratuito e completo, módulo a módulo, com exercício em cada um.
  • 📄 HTML Acessível — MDN A base: como a marcação correta resolve a maior parte dos problemas.

🎥 Curadoria de vídeo pendente. Este bloco recebe os vídeos de apoio selecionados pelo instrutor para o tema acima.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: abra uma tela sua e guarde o mouse longe — a prática inteira é sem ele.
  2. Diagnóstico com Tab: percorra a tela só com Tab e anote onde o foco some ou pula.
  3. Corrigindo o Foco Visível: remova qualquer outline: none e use :focus-visible.
  4. Conferindo a Ordem: garanta que a ordem de foco segue a ordem visual da tela.
  5. Trocando por Semântica: substitua <div onclick> por <button> onde houver ação.
  6. Rotulando Campos: ligue cada input a um label por for e id.
  7. Texto Alternativo: descreva as imagens informativas e deixe alt=\"\" nas decorativas.
  8. Testando com Leitor de Tela: ligue o Narrador no Windows ou o VoiceOver no Mac e percorra a tela.
  9. Medindo o Contraste: use o DevTools para conferir a razão de cada texto sobre seu fundo.
  10. Validação e Testes: complete a tarefa principal da tela do começo ao fim sem tocar no mouse.
Concluiu todos os passos?

🧩 3. Do Token ao Componente Reutilizável

Com tokens definidos e acessibilidade no lugar, o componente deixa de ser um pedaço de HTML copiado e vira uma peça com contrato: o que recebe, o que faz, quais estados tem.

  • 📄 Catálogo de Componentes — Material 3 Cada componente com anatomia, estados e regras de uso — bom modelo de documentação.
  • 📄 Padrão de Botão Acessível — ARIA APG O que um botão precisa ter para funcionar com teclado e leitor de tela.
  • 📄 :focus-visible — MDN Como mostrar o foco para quem navega por teclado sem poluir para quem usa mouse.
  • 📄 Storybook — documentação oficial A ferramenta padrão para catalogar componentes isolados com seus estados.

🎥 Curadoria de vídeo pendente. Este bloco recebe os vídeos de apoio selecionados pelo instrutor para o tema acima.

Siga os 10 passos abaixo para construir a prática aplicando os conceitos do bloco:

  1. Configuração do Ambiente: crie componentes.html importando os tokens do bloco 1.
  2. Definindo o Contrato: escreva num comentário quais variações e tamanhos o botão terá.
  3. Estado Padrão: implemente a variação primária com os tokens semânticos, sem cor literal.
  4. Hover e Ativo: acrescente as duas mudanças de estado, com transição curta.
  5. Foco Visível: use :focus-visible com contorno de ao menos 3:1 de contraste.
  6. Desabilitado: use o atributo disabled e estilize por [disabled], não por classe.
  7. Estado de Carregando: acrescente indicador e aria-busy=\"true\" enquanto processa.
  8. Variação Secundária: crie a segunda variação trocando apenas tokens, sem duplicar as regras.
  9. Página de Catálogo: monte uma grade mostrando as duas variações em todos os seis estados.
  10. Validação e Testes: percorra o catálogo só com Tab e confirme que todo estado é perceptível sem mouse.
Concluiu todos os passos?
